## 1. Contract

```
LearningContext {
  contextId, situation, lifecycle,

  observations[]     → Capability-driven world observation
  evidenceIds[]      → Immutable evidence artifacts
  signalIds[]        → Derived business signals

  agentActivities[]  → What the agent did (observable, not internal)

  humanInterventions[] → Professional input (optional)
    respondsToActivityIds → Which agent activity prompted this (Case C)
  actions[]            → Real-world changes (optional)
  outcomes[]           → Re-observed results (optional)
    relatedActionIds   → Actions that preceded outcome (not causal)

  summary              → Aggregated metadata (not provenance)
  (Real provenance: ID reference chains across fields. P0007.5.)
}
```

### Situation/Case — the business anchor

Every Learning Context is about a specific business situation — not a chat message, not a task ID. The Situation provides domain, entity, temporal scope, and business description.

### Lifecycle

| State | Condition |
|-------|-----------|
| `open` | Observations + agent activity exist; no human input yet |
| `partial` | Human intervention or action has occurred |
| `mature` | Real-world outcomes have been observed |

Partial contexts are valid — agentFabric records what exists without waiting for completion.

### Runtime-Neutral

Schema contains zero Hermes-specific fields. Any Agent Runtime can consume a Learning Context. `agentRuntime` field records who did what, not who should consume.
