# P0007.1 Time Handling Audit

**Scope**: `shared/schemas/learning-context.ts`, `tests/contract/learning-context.contract.ts`
**Finding**: No production leak. One test conflation.

---

## 1. Production Schema — No Hardcoded Time Defaults ✅

All time fields use bare `IsoDateString` from `./common.js`. No `.default()` on any time field.

```
Situation.temporal.observedAt        IsoDateString  (no default)
ObservationRef.observedAt            IsoDateString  (no default)
AgentActivityRef.timestamp           IsoDateString  (no default)
HumanIntervention.timestamp          IsoDateString  (no default)
ActionRef.timestamp                  IsoDateString  (no default)
OutcomeRef.observedAt                IsoDateString  (no default)
LearningContext.createdAt            IsoDateString  (no default)
LearningContext.updatedAt            IsoDateString  (no default)
```

The only defaults in the schema are:
- `lifecycle: 'open'` (lifecycle state, not time)
- `agentRuntime: 'hermes'` (label, not time)
- `metricsSnapshot: {}` (data, not time)
- Arrays defaulting to `[]`

**No time value is ever defaulted by the schema.** ✅

## 2. Production Builder — Does Not Exist ✅

No `buildContext`, `createContext`, `assembleContext`, or context builder exists in production code. Only:
- `LearningContextSchema` (Zod validation)
- `isLearnable(ctx)` (boolean check)
- `determineLifecycle(ctx)` (lifecycle state)

These are pure functions — they consume `LearningContext`, they don't create it.

## 3. JD Real Validation Test — Minor Conflation ⚠️

```typescript
// Line 176-180:
temporal: { observedAt: meta.acquired_at, ... },  // ✅ evidence acquisition time
createdAt: meta.acquired_at,                        // ⚠️ conflation
updatedAt: meta.acquired_at,                        // ⚠️ conflation
```

The issue: `meta.acquired_at` is "when the CDP evidence was captured". Using it for `ObservationRef.observedAt` is correct. Using it for `LearningContext.createdAt` conflates two distinct times:

```
Evidence acquisition time               (meta.acquired_at)
  ≠
Learning Context creation time          (when context was first assembled)
  ≠
Observation recorded time               (when observation was added to context)
```

This is a **test-only** conflation. The test creates the Context at roughly the same time as the evidence exists, so the values happen to be the same. But the semantic distinction matters for future production code.

## 4. Test Fixture Times — Acceptable ⚠️

Tests use hardcoded timestamps like `'2026-08-12T02:38:00Z'`. These are spread across the file without a central constant.

**Acceptable**: unit tests need deterministic inputs. `new Date()` in tests would make them non-deterministic. But a `TEST_TIMESTAMP` constant would make the relationship between times in different fixtures explicit (T0 → T0+2min → T0+30min).

## 5. Semantic Distinction Checklist

| Time | Meaning | Source | Verified |
|------|---------|--------|----------|
| `Situation.temporal.observedAt` | When the business situation was first detected | External observation | ✅ Schema clear |
| `ObservationRef.observedAt` | When the data was observed/captured | Evidence metadata (`meta.acquired_at`) | ✅ Schema clear |
| `AgentActivityRef.timestamp` | When the agent performed this activity | Execution event | ✅ Schema clear |
| `HumanIntervention.timestamp` | When the human intervened | Event recording | ✅ Schema clear |
| `ActionRef.timestamp` | When the action was taken | World change event | ✅ Schema clear |
| `OutcomeRef.observedAt` | When the outcome was re-observed | Re-observation event | ✅ Schema clear |
| `LearningContext.createdAt` | When this context document was first assembled | Context assembler | ✅ Schema clear |
| `LearningContext.updatedAt` | When this context was last enriched | Context assembler | ✅ Schema clear |

## 6. Recommendation

**No production changes needed.** Two minor test improvements:

1. JD test: distinguish `createdAt` from `observedAt` — use a separate timestamp for context creation
2. Test fixtures: add `TEST_TIMESTAMP` constant for fixture clarity

These are cosmetic. No time handling bug exists.
