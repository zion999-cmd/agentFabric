# P0005.2: Discovery-Driven Connector Architecture

**Status:** Proposed  
**Date:** 2026-06-30  
**Depends on:** P0005 (Business Data Foundation), P0005.1 (JD Business Data Connector), D0002 (JD Capability Discovery)

---

# Objective

P0005.1 已验证：

```
Acquisition
    ↓
Evidence
    ↓
Parse
    ↓
Normalize
```

能够完整工作。

P0005.2 不再解决"如何采集数据"，而是解决：

> **Connector 如何持续理解自己的数据能力。**

AgentFabric 的 Connector 不应该依赖人工维护 API 列表、指标映射和 Business Context。

Connector 必须能够通过 Discovery 自动理解：

- 自己有哪些能力
- API 是否发生变化
- 新指标是否出现
- Business Context 是否需要更新

最终实现：

```
Discovery
        ↓
Capability Model
        ↓
Connector
        ↓
Business Context
```

而不是：

```
人工维护
        ↓
Connector
```

---

# Motivation

D0002 已发现：

- 70 个 API
- 26+ 指标
- 7 个 Business Context
- 多个 API Module

但目前 Connector 仍然：

- 手工维护 API
- 手工维护 indicator-map
- 手工维护 manifest
- 手工声明 Business Context

Discovery 与 Connector 之间存在明显断层。

P0005.2 用于消除这条断层。

---

# Core Principle

Discovery 永远是真实来源（Source of Truth）。

Connector 永远不主动定义业务能力。

Connector 只消费 Discovery。

即：

```
Discovery
        ↓
Capability
        ↓
Connector
```

而不是：

```
Connector
        ↓
Capability
```

# Phase 1 — API Discovery Integration

Connector 不再维护：

```
summary.ajax
trend.ajax
productTop.ajax
```

而是：

```
Discovery

↓

API Inventory

↓

Connector 自动注册能力
```

例如：

```
Discovery

↓

70 APIs

↓

Connector 自动知道：

Industry

Customer

Marketing

Traffic

Product

Store

SupplyChain
```

---

# Phase 2 — Schema Evolution

每个 API 保存：

```
Endpoint

Schema

Hash

Version

Last Seen
```

例如：

```
summary.ajax

↓

Schema Hash

↓

f1ac82...

↓

京东升级

↓

Hash Changed

↓

Connector 自动发现变化
```

以后：

任何平台升级，

Connector 都能够自动发现。

---

# Phase 3 — Indicator Dictionary

目前：

```
indicator-map.ts

↓

人工维护
```

升级为：

```
Discovery

↓

Indicator Dictionary

↓

Canonical Metric
```

例如：

```
jdr_sch_trade_deal_ord_ord_amt_sz_trade_deal_snapshot

↓

Transaction

↓

GMV
```

新增指标：

无需修改 Parser。

Dictionary 自动更新。

---

# Phase 4 — Capability Matrix

Discovery 自动维护：

```
Capability Matrix
```

例如：

| Module | APIs | Context | Status |
|---------|------|----------|--------|
| Store | 12 | ✓ | Available |
| Traffic | 18 | ✓ | Available |
| Customer | 9 | ✓ | Available |
| Marketing | 11 | ✓ | Available |
| Industry | 14 | ✓ | Available |
| SupplyChain | 6 | ✓ | Available |
| Competition | 8 | Subscription Required |

Connector 不维护这张表。

Discovery 自动生成。

---

# Phase 5 — Business Context Generation

Business Context 不允许人工声明。

例如：

错误方式：

```
manifest.ts

↓

business_context:

Store

Traffic

Customer
```

正确方式：

```
Discovery

↓

Field Analysis

↓

Business Context

↓

Generated Manifest
```

Business Context 必须来自：

真实 API 字段。

而不是：

程序员判断。

---

# Connector Responsibilities

Connector 只负责：

```
Acquire Data

↓

Capture Evidence

↓

Execute Discovery

↓

Expose Capability
```

不负责：

```
Business Definition

Skill Definition

Decision Logic
```

---

# Discovery Responsibilities

Discovery 负责：

- API Inventory
- Endpoint 分类
- Schema Version
- Schema Hash
- Indicator Dictionary
- Capability Matrix
- Business Context Candidate
- Platform Capability Report

Discovery 是平台能力。

不是某个平台 Connector 的能力。

---

# Business Context Principle

Business Context 永远来自：

```
Evidence

↓

Discovery

↓

Verification

↓

Business Context
```

绝不能来自：

```
程序员声明
```

---

# Expected Benefits

完成后：

新增一个平台：

```
Tmall
```

只需要：

```
Discovery

↓

Capability

↓

Connector
```

Skill、

Decision、

Experience、

Review

全部无需修改。

Connector 具有平台无关性。

---

# Success Criteria

- Discovery 自动维护 API Inventory
- Discovery 自动维护 Capability Matrix
- Discovery 自动维护 Indicator Dictionary
- Discovery 自动检测 API Schema 变化
- Connector 不再维护 API 列表
- Connector 不再维护 Business Context
- Connector 不再维护 Indicator Mapping
- Business Context 全部来自 Discovery
- 新平台（Tmall）无需修改业务层即可接入
