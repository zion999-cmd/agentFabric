本次用 **3 个确定存在于 world/ 且能唯一回答的事实** 重新测 World consumption。

## 4. 结论

**World discovery gap 确认成立。**

即使 3 个事实**明确存在于 world/**，Blank Agent 仍然：
1. Fact 1：反问"哪家店铺"（不知道 world/systems/jdsz.md 有 shop 信息）
2. Fact 2/3：直接 web_search（不读 world/）

这与原 Probe A 不同——这次排除了 Content Gap（答案是确定存在的），所以失败归因清晰：

> **Discovery / Orientation Failure：Blank Agent 不知道 world/ 里有答案，也没有一个 navigation entrypoint 引导它进入 world/。**

---

## 5. 与 Knowledge 的不对称（确认）

```
knowledge/
├── INDEX.md        ← 有 navigation entrypoint
└── marketing-strategy-framework.md

world/
├── systems/        ← 无 navigation entrypoint
├── surfaces/
├── metrics/
├── dimensions/
└── constraints/
```

Knowledge 有 `INDEX.md`（导航入口），Blank Agent 能 search_files → INDEX → 找到主题（Probe B/C 通过）。

World 缺 `INDEX.md`（World Map），Blank Agent 需自己理解 ontology 和目录结构才能导航，导致走 web_search。

---

## 6. 修正方向（供 Review，不实现）

用户已指出：**缺的不是 Search API / RAG，而是非常简单的 `world/INDEX.md`（World Map / navigation entrypoint）**。

`INDEX.md` 不是知识本身，也不 flatten World，它只告诉 Agent：
- 这个 world 描述什么系统
- 有哪些主要 Surface / Metric domain / Dimension / Constraint
- 遇到什么问题应该往哪里找
