# P0008.5 — Minimal World + Knowledge Bootstrap E2E (Test Plan)

**Date**: 2026-08-14
**Depends on**: P0008.2 / P0008.3 / P0008.4
**Type**: Test Plan — scope-corrected, NOT implementation

---

## 1. Objective

P0008.5 不扩大测试范围。只验证三个核心假设：

1. **已有 World Exploration Artifact 能否被 Fabric 组织成标准 Agent Context Environment**
2. **任意外部文档能否按 P0008.4 Shared Knowledge 机制被 Agent 整理为 Markdown Knowledge**
3. **一个新的 Blank Agent 能否进入该 Workspace，自主检索和使用 World + Shared Knowledge**

暂不测试：Situation / Learning Context / Evidence / 复杂业务推理。

---

## 2. Test Environment

- 独立工作目录，例如 `/Users/bx/Workspace/agentfabric-p0008.5-test/`
- 创建新的 Hermes project/profile
- 只要求确认初始 profile 中无明显 JD-specific：Soul / Memory / Skill / Session history
- 使用 Hermes 自身 project/profile/session 隔离即可
- **不清理全局 ~/.hermes**
- **不做复杂 clean-room**

---

## 3. 核心链路（本实验最核心）

```
Agent A 曾经探索世界
        ↓
WorldExplorationTask
        ↓
Fabric Context / Governance
        ↓
Preparation Agent 整理
        ↓
world/

Human 添加任意文档
        ↓
raw/
        ↓
Preparation Agent
        ↓
knowledge/

然后：

新的 Blank Agent
        ↓
同一个 Workspace
        ↓
自主使用 world/ + knowledge/
```

---

## 4. Phase A — Seed Existing World

- World Source 使用 `/Users/bx/Workspace/WorldExplorationTask/`（Hermes 已真实探索产生）
- **不重新探索京东商智**
- 这些 Artifact 是"已被探索、但尚未按当前 Fabric Context Contract 整理的 World Source"
- 同时提供 agentFabric 已定义的：
  - P0008.2 World Model Contract
  - Capability definitions / Capability Registry docs
  - P0008.3 Workspace Contract
  - P0008.4 Shared Knowledge Governance

---

## 5. Phase B — Context Structure Generation Test

使用一个 **Preparation Hermes Session**。目标不是回答业务问题，而是验证：Fabric 当前 Contract + Governance 是否足以指导 Agent 将已有 World Source 组织成标准 Workspace。

目标结构大致为：

```
workspace/
├── AGENTS.md
├── world/
├── knowledge/
│   ├── KNOWLEDGE.md
│   └── INDEX.md
├── knowledge-sources/
│   └── raw/
└── capabilities/
```

**约束**：
- 文件数量和分类**不硬编码**（观察 Agent 是否根据 Contract 自行形成合理结构）
- 保留 World Source provenance
- 不重新 JD Discovery
- 不 web search 补 World

---

## 6. Phase C — Arbitrary Knowledge Ingestion Test

Workspace 建立后，人工加入一份新的外部文档。

- 格式任选真实常见格式（PDF / TXT / HTML / Markdown / DOCX）
- **优先非 Markdown 格式**，证明 Shared Knowledge Layer 不是"复制 Markdown 文件"
- 内容不需复杂（营销案例 / 推广方法 / 平台规则 / 企业 SOP / 行业资料）

放入 `knowledge-sources/raw/`，然后给 Agent 一个自然任务：

> "把刚加入的资料整理进共享知识。"

**不告诉它**：输出文件名 / Markdown schema / 创建几页 / 写到哪个分类。

这些应由 AGENTS.md + KNOWLEDGE.md 指导 Agent。

---

## 7. Phase D — Knowledge Compilation Acceptance

检查：

1. Raw source 是否保持不变
2. Agent 是否读取 KNOWLEDGE.md
3. 是否产生 Agent-readable Markdown
4. 是否保留 provenance
5. INDEX 是否正确更新
6. 是否更新已有页面（而非机械 source→file）
7. 是否没有把 Shared Knowledge 写进 world/
8. 是否没有把知识写入 Hermes Memory/Skill 代替 Shared Knowledge

**不要求实现 Fabric KnowledgeCompiler**。Compilation 由 Hermes 原生 reasoning + file tools 完成。Fabric 只提供 Environment + Contract + Governance。

---

## 8. Phase E — Freeze Workspace

完成 World + Knowledge 后冻结 Workspace。记录：

- directory tree
- relevant file hashes
- World source mapping
- Knowledge raw → compiled mapping

之后不再使用 Preparation Session。

---

## 9. Phase F — Blank Agent Consumption Test

创建新的 Hermes project/profile/session，它**没有参与 Phase A-D**，cwd 指向冻结的 Workspace。

只进行两个最小 Probe。

### Probe 1 — World

问一个只能从 WorldExplorationTask 派生 World Knowledge 可靠回答的问题（如"竞品对比有哪些指标？"）。不提示 world/ 或文件名。验证 Blank Agent 是否自主发现并使用 World。

### Probe 2 — Shared Knowledge

问一个答案只存在于 Phase C 新加入文档中的问题。不提示 knowledge/、raw source 或文件名。验证 Blank Agent 是否自主发现并使用 Shared Knowledge。

### Optional Probe 3 — Combined

仅当前两个通过后，问一个同时需要 World + Shared Knowledge 的简单问题。只观察 Agent 能否跨两个 Context Source 使用信息。不扩展成复杂业务 Agent Evaluation。

---

## 10. PASS Criteria

P0008.5 PASS 只需证明：

- **A.** Existing World artifacts → Fabric Context structure
- **B.** Arbitrary Raw Document → Agent-maintained Markdown Shared Knowledge
- **C.** Blank Runtime → autonomous discovery of World Knowledge
- **D.** Blank Runtime → autonomous discovery of Shared Knowledge

A-D 成立即本阶段完成。
