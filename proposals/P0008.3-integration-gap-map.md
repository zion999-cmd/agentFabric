## A. agentFabric 现有 Hermes Integration 现状

### A1. Fabric 当前通过什么机制与 Hermes 通信？

**唯一机制：无状态 one-shot 子进程**。

```typescript
// SubprocessHermesClient.oneShot()
spawn('hermes', ['-z', prompt]) → stdout 捕获 → resolve
```

- `hermes -z` = oneshot，只打印最终响应到 stdout
- 每次 turn 一个新进程，进程结束即销毁
- 加载 SOUL/memory/config/skills 从磁盘，但**不保持进程内连续性**

### A2. 是否已经能启动/连接指定 Hermes profile？

**不能。** `buildArgs()` 只传 `-z`/`-m`/`--provider`/`-t`/`--skills`/`--safe-mode`。**没有 `-p <profile>` 参数**。Profile 选择完全交给 Hermes 的默认逻辑（`~/.hermes` 或 sticky `active_profile`）。

### A3. 是否能创建、继续、恢复 Hermes session？

**不能。** 无 `session.create`/`session.resume`/`--resume`/`--continue`。每次 `-z` 都是一个新 session（且 `-z` 不打印 session_id，需 `--usage-file` 才能恢复）。

### A4. CBP Hermes Connector 当前负责什么？

**不存在。** `grep -rln "CBP\|CognitiveBridge"` 在 agentFabric 源码中零命中（只有文档/audit 提及）。CBP 是独立项目（`/Users/bx/Workspace/bridge`），agentFabric 没有集成它。

### A5. Workspace Chatbox 当前链路实际到哪里？

```
Workspace Chatbox (app.js chatSendButton)
  ↓ POST /api/chat  { message }
  ↓ matchIntent()  → Hermes oneShot #1 (意图分类)
  ↓ dispatchHandler() → kernel.execute / orchestrator.rank / facade.*
  ↓ generateResponse() → Hermes oneShot #2 (回复生成)
  ↓ reply 文本
```

每消息 = 2 次无状态 Hermes one-shot，**无会话连续性**。Chatbox 不连接到任何 Hermes session。

### A6. 让 Chatbox 成为 Hermes Session UI，缺失的最小工程层？

| 缺失 | 说明 |
|------|------|
| Profile 选择 | 无 `-p` / profile 概念 |
| cwd/workspace 指定 | 无 `terminal.cwd` / `session.create(cwd=...)` |
| Session create/resume | 无 WebSocket JSON-RPC 或 `--resume` |
| 常驻 process 管理 | 无 `hermes serve`/dashboard 生命周期 |
| Event streaming | 无 `/api/ws` 连接，只有一次性 stdout |

## B. Hermes Runtime 能力（源码确认，非假设）

### B1. Profile 如何选择

Profile = 目录 `~/.hermes/profiles/<name>/`（含 `SOUL.md`/`memories/`/`sessions/`/`skills/`/`plans/`/`workspace/`/`config.yaml`/`state.db`）。

选择顺序（`hermes_cli/main.py:_apply_profile_override`）：
1. `-p <name>` / `--profile=<name>`
2. sticky `~/.hermes/active_profile` 文件
3. 默认 `~/.hermes`

### B2. cwd/workspace 如何指定

**无 `--cwd`/`--workspace` 全局 flag。** cwd 解析顺序（`agent/runtime_cwd.py`）：
1. per-session `_SESSION_CWD` contextvar（`session.create` 显式 `cwd` 参数）
2. `TERMINAL_CWD` env（来自 config `terminal.cwd`）
3. `os.getcwd()`（启动目录）

**cwd 是 invocation-level + session-level**，不是 profile-level。`sessions` 表存 `cwd`/`git_repo_root`/`git_branch`/`profile_name` per row。

### B3. Session create/resume

- CLI: `--resume/-r <SESSION>`（by ID/title）、`--continue/-c`
- JSON-RPC: `session.create`（params: cwd/profile/model/parent_session_id/...）→ 返回 8-hex `sid`；`session.resume`（by ID/prefix/title，恢复完整祖先历史 + cwd/model/profile）
- Session 身份 = `state.db` `sessions` 表 `id`（SQLite，非文件）

### B4. Programmatic interface（适合长期 Chatbox）

Hermes 暴露 **5 个接口**：

| 接口 | 形态 | 适合 Chatbox? |
|------|------|--------------|
| one-shot `-z` | CLI 子进程，仅 stdout | ❌ 无状态 |
| Interactive TUI/REPL | 终端 | ❌ |
| **dashboard/serve WebSocket** | `/api/ws` JSON-RPC + `/api/sessions` REST | ✅ **这是目标** |
| headless `hermes serve` | 同 dashboard，无 SPA（`HERMES_SERVE_HEADLESS=1`） | ✅ 后端 |
| messaging gateway | WhatsApp/Telegram 等 | ❌ 非通用 HTTP |

**关键**：`hermes serve`（默认 port 9119）暴露 `/api/ws` WebSocket，JSON-RPC 2.0 协议：`session.create` → `prompt.submit` → `event` stream。这是 desktop/TUI 用的同一协议，是**官方长期接口**。另有 `/api/pty`（跑 `hermes --tui` 桥接 ANSI）。

**无简单 `POST /api/chat` REST 端点**——turn 只通过 WebSocket JSON-RPC。

### B5. 一个 profile 多个 session 的 identity/lifecycle

**支持。** 进程内 `_sessions: dict[sid → session]` + `state.db` per-profile。每个 session 独立 cwd/model/history。一个 dashboard 可服务所有 profile（`?profile=` 路由）。

### B6. cwd 是 profile/session/invocation-level？

**invocation-level + session-level**（非 profile-level）。`session.create` 显式 `cwd` 参数可 pin。

### B7. 是否需要常驻 Hermes process？

**是（对于长期 Chatbox）。** `hermes serve`/dashboard/gateway 是常驻进程。`-z` 是 stateless resume-from-disk（每次新 session）。长期 Chatbox 需要保持一个 `hermes serve` 进程。

## C. Agent Workspace Gap

### Fabric 至少需要向业务 Runtime 暴露的类别

```
Fabric Agent Workspace（干净目录）
├── world/            World Knowledge（P0008 World Model）
├── situation/        Current Situation（P0007）
├── evidence/         Evidence references
├── capability/       Capability descriptions/bindings

### 绝不能进入

```

❌ tests/
❌ proposals/
❌ historical implementation artifacts（discovery/ jd_shangzhi_features/ WorldExplorationTask/）
❌ Hermes SOUL / Memory / Skills / Sessions（Hermes Profile 自己管理）

**边界**：Hermes Runtime Self（SOUL/Memory/Skills/Sessions/Plans）继续由 Hermes Profile 管理。agentFabric 只提供一个干净的 cwd（Fabric Agent Workspace），让 Hermes 在那里 filesystem-native 地发现 World Knowledge。

## 结论

**最关键的单点发现**：agentFabric 当前用 `hermes -z`（无状态 one-shot），而 Hermes 已提供完整的 `/api/ws` JSON-RPC session 协议（`session.create`/`prompt.submit`/event stream）。要让 Chatbox 成为 Hermes Session UI，**不需要重新实现任何 session 能力**——只需要：

1. 一个 Fabric Agent Workspace（干净 cwd）
2. 一个薄 HermesSessionClient（speak 现有 JSON-RPC）
3. Chatbox 接线到它

Hermes 已经解决了 profile/session/cwd/resume/streaming 的 95%。agentFabric 缺的是"接入层"和"干净 workspace"，不是任何 runtime 能力。
