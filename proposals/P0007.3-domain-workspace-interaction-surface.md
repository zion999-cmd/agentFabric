# P0007.3 — Domain Workspace & Interaction Surface

**Status**: Proposal
**Date**: 2026-08-12
**Depends on**: P0007.2 Human Intervention Infrastructure, Phase 2 Workspace UI
**Type**: Architecture + UI Design

---

## 1. Objective

将旧 Workspace 的中心对象从"AI Findings / 功能模块"重构为 **Situation Workspace**。

旧 UI 已经有完整的 SPA 外壳和"运营工作台"的形——保留它。重构的是中心对象。

```
旧 Workspace                      P0007.3
────────────────────────────────────────────
今日发现        ───────────→   Situation Feed
Finding Card    ───────────→   Situation Card
审核中心        ───────────→   Human Intervention
AI Explain      ───────────→   Agent Interpretation
Recommendation  ───────────→   Agent Proposal
Evidence        ───────────→   Evidence Drawer
Chat            ───────────→   Situation-scoped Chat
Review          ───────────→   Interaction Surface

Memory UI       ───────────→   Legacy / Hide
Agent Config    ───────────→   Runtime ownership / Hide
Capability      ───────────→   Advanced
Runtime         ───────────→   Advanced
```

---

## 2. Core Design Principle

**Situation is the primary Workspace object, not a chat message or an Agent output.**

### 2.1 Master → Detail → Intervention

```
┌──────────────────────────────────────────────────────────┐
│ 今日经营                                       12 Aug   │
├──────────────┬───────────────────────────────────────────┤
│              │                                           │
│ Situations   │ 商品 A · 点击效率异常                      │
│              │                                           │
│ ● 待处理  6  │ ┌─ 发生了什么 ─────────────────────────┐ │
│              │ │ 搜索曝光 ↑23%                          │ │
│ ● Agent中  2 │ │ CTR ↓17% · 连续3天                    │ │
│              │ └────────────────────────────────────────┘ │
│ ● 已处理  4  │                                           │
│              │ Agent 判断                                │
│              │ 流量增加但点击效率持续下降……               │
│              │                                           │
│              │ Agent 建议                                │
│              │ 优先检查商品主图，暂不调整价格              │
│              │                                           │
│              │ [为什么？ 查看 Evidence]                   │
│              │                                           │
│              ├───────────────────────────────────────────┤
│              │ 你的判断                                  │
│              │                                           │
│              │ [认同] [判断有误] [补充情况]               │
│              │                                           │
│              │ 你准备怎么处理？                           │
│              │ [暂不处理] [准备处理...]                   │
│              │                                           │
└──────────────┴───────────────────────────────────────────┘
```

### 2.2 Grammar → Business Language Mapping

后台 5-type Grammar 不直接暴露给运营人员。Workspace 翻译成业务自然动作：

| 后台 Grammar | Workspace 语言 | 触发方式 |
|-------------|---------------|---------|
| `response` | Agent 判断 → [认同] | 点击"认同" |
| `correction` | Agent 判断 → [这里判断错了] | 点击 + 填写修正 |
| `context_supplement` | Agent 判断 → [还有一个你不知道的情况] | 点击 + 填写信息 |
| `decision` | 你准备怎么处理？→ [暂不处理] [稍后处理] [不采用] | 选择 |
| `action_intent` | 你准备怎么处理？→ [我准备这样处理…] | 填写意图描述 |

**Workspace 绝不展示 "请选择 Human Intervention Type"。**

## 3. Navigation Restructuring

### 3.1 Sidebar: Business-First

```
今日工作                            ← NEW top section
├── 全部 Situation
├── 待我处理              (badge)
├── Agent 处理中           (badge)
├── 已处理
└── 待观察结果

经营观察                            ← Existing, renamed
├── 商品
├── 流量
├── 转化
└── 趋势

────────────────

系统/高级                           ← Downgraded
├── Evidence
├── Agent Runtime
└── Capability

────────────────

Legacy                             ← Hidden/collapsed
├── Memory 成长
└── Agent 配置
```

### 3.2 What Changes

| 旧元素 | 新元素 | 操作 |
|--------|--------|------|
| 今日发现 / 增长机会 / 风险预警 / 审核中心 | 全部 Situation / 待我处理 / Agent 处理中 / 已处理 / 待观察结果 | **Replace section** |
| Finding Card | Situation Card | **Evolve** |
| 商品分析 / 趋势观察 / 历史归档 | 商品 / 流量 / 转化 / 趋势 | **Rename, preserve** |
| Capability / Evidence / Runtime | 移入 "系统/高级" | **Downgrade** |
| Memory 成长 / Agent 配置 | 隐藏或标记 Legacy | **Hide** |
| 首页底部 Chat | Situation-scoped Chat | **Reposition** |
| Decision Panel (右侧) | Evidence Drawer + Intervention Surface | **Repurpose** |

## 4. Situation Feed

### 4.1 Card Structure

每个 Situation Card 显示：

```
┌─ Situation Card ──────────────────────────────────────┐
│                                                       │
│ 商品 A · 点击效率异常                    ● 待处理      │
│                                                       │
│ 发生了什么                                            │
│ 搜索曝光 ↑23% · CTR ↓17% · 连续3天                    │
│                                                       │
│ Agent 建议                                            │
│ 优先检查主图，暂不调整价格                             │
│                                                       │
│ ─────────────────────────────────────────────────────  │
│ 12 Aug 02:38 · 3 个信号 · 2 条干预 · [查看详情 →]     │
└───────────────────────────────────────────────────────┘
```

### 4.2 Feed Organization

| Tab | 内容 | 来源 |
|-----|------|------|
| 全部 | 所有 Situation | `GET /api/situations` |
| 待我处理 | lifecycle=open 的 Situation | 无干预或最新活动是 Agent |
| Agent 处理中 | 有 agentActivity 但无最近 intervention | taskId 活跃 |
| 已处理 | lifecycle=partial 的 Situation | 有 intervention |
| 待观察结果 | lifecycle=partial + 有 action_intent | 等待 Outcome (P0007.4) |

### 5.2 Business Language → Grammar Mapping

Workspace 翻译业务动作到 P0007.2 Grammar。用户不需要知道 Grammar 存在。

```
[认同 Agent 判断]  →  POST intervention { type: "response", evaluation: "agree" }
[这里判断错了]      →  POST intervention { type: "correction", corrects: {...} }
[还有一个你不知道的情况] → POST intervention { type: "context_supplement", information: "..." }
[采用建议]          →  POST intervention { type: "decision", decision: "accept" }
[不采用]            →  POST intervention { type: "decision", decision: "reject" }
[稍后处理]          →  POST intervention { type: "decision", decision: "defer" }
[我准备这样处理…]   →  POST intervention { type: "action_intent", description: "..." }
```

## 7. Situation-Scoped Chat

Chat 保留但降级为 Situation 上下文中的补充交互。

```
┌─ Chat ──────────────────────────────────────────────────┐
│ 你 > 为什么你认为是主图问题？                             │
│                                                          │
│ Agent > 过去 30 天，该商品 CTR 为 2.5%。                  │
│ 8月10日起连续3天降至2.1%。搜索曝光同期↑23%，               │
│ 说明流量质量没有下降。                                    │
│ 同时期竞品 CTR 稳定在2.6%，排除行业因素。                  │
│                                                          │
│ 你 > 把最近 14 天搜索流量展开                             │
│                                                          │
│ Agent > [展开数据...]                                     │
│                                                          │
│ ┌─ 追问 ──────────────────────────────────────────┐     │
│ │ 竞争商品有什么变化？                              │     │
│ │ 转化漏斗每一层的数据？                            │     │
│ └──────────────────────────────────────────────────┘     │
└──────────────────────────────────────────────────────────┘
```

**Chat belongs to a Situation.** 不是独立的 Agent Session 页面。

这意味着 Chat 内容天然进入 Situation 的 Learning Context（Agent Activity），而不是散落的 conversation history。

## 10. Success Criteria

- [ ] 第一个京东运营人员看到的是 Situation（"商品 A · 点击效率异常"），不是 traffic.overview / evidenceId / capabilityId
- [ ] 运营人员通过自然业务动作（认同/判断有误/补充情况/暂不处理/准备处理）产生 Intervention，不需要知道 Grammar
- [ ] 每个 Intervention 正确映射到 P0007.2 Grammar type，持久化到 `human_interventions` 表
- [ ] Situation lifecycle 在首次干预后从 open → partial
- [ ] Evidence Drawer 展示 provenance 链，但业务主界面不暴露证据 ID
- [ ] Situation-scoped Chat 产生的对话可作为 Agent Activity 进入 Learning Context
- [ ] Memory 成长 / Agent Config 页面标记 Legacy 并隐藏
- [ ] Capability Explorer / Evidence Viewer / Runtime 降级到高级区域
- [ ] 旧 UI 的 Inbox / Product / Trend / Archive 功能保留并可用
- [ ] `action_intent` 保持 Hypothesis——不强制 UI，观察运营人员自然行为
