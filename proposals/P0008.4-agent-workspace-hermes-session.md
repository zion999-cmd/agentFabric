# P0008.4 — Agent Workspace & Hermes Session Integration

**Date**: 2026-08-13
**Depends on**: P0008.2 World Model Contract, P0008.4 Integration Gap Map
**Type**: Design Proposal — no implementation

---

## 1. Objective

打通 P0008 最核心的一条链：

```
World → Workspace → Agent
                     ↕
                   Human
                     ↓
                Experience
                     ↓
              Memory / Skill
```

一个全新的 Hermes Profile，通过 Situation Chat 创建 Session，Session cwd 指向干净的 Fabric Workspace；它能自主读取 JD World Knowledge、保持多轮 Session，并且它产生的 Memory/Skill 只进入自己的 Hermes Profile。

---

## 2. 三个工程对象

### 2.1 FabricAgentWorkspace

**定义**：authoritative state → runtime-facing workspace 的投影。

Fabric 的 authoritative state（World Model / Situation / Evidence / Capability）不能直接作为 Hermes 的 cwd——agentFabric repo 有大量 semantic noise（源码/tests/proposals/discovery）。FabricAgentWorkspace 是一个干净的目录，只含 Hermes 需要"看见"的业务知识。

```
fabric-workspace/
├── README.md                 ← workspace orientation（"你进入的是京东电商世界"）
├── world/
│   └── jd_shangzhi/
│       ├── system.md         ← System（京东商智是什么）
│       ├── surfaces.md       ← Surfaces（交易概况/流量/商品/...）
│       ├── metrics.md        ← Metrics（成交金额/成交单量/客单价/...）
│       ├── dimensions.md     ← Dimensions（时间/渠道/对比）
│       └── constraints.md    ← Constraints（数据新鲜度/付费墙）
├── situation/
│   └── current.md            ← 当前 Situation（今日经营异常）
├── evidence/
│   └── references.md         ← Evidence references（哪个事实来自哪个证据）
└── capability/
    └── bindings.md           ← Capability bindings（哪个 Metric 可被哪个 Capability 观察）
```

**关键原则**：
- Workspace 是**投影**（generated from authoritative state），不是 authoritative state 本身
- Workspace 只含**业务知识**，不含 source/tests/proposals/discovery/Hermes SOUL
- Hermes 通过 filesystem-native discovery 读取这些文件（Hermes 已有此能力，见 Gap Map）

**P0008.4 范围**：只用 JD fixture 做一个最小 projection，不做全量 Markdown Projector。

### 2.2 HermesSessionClient

**定义**：一个薄客户端，speak Hermes 现有的 `/api/ws` JSON-RPC 协议。

复用 Hermes 已提供的（不重新实现）：
- profile 选择
- session create / resume / list
- prompt submit
- event stream

```typescript
// 接口契约（示意，非实现）
interface HermesSessionClient {
  // 连接 hermes serve /api/ws
  connect(profile: string, cwd: string): Promise<void>;

  // Session 管理
  createSession(opts: { cwd: string; profile: string }): Promise<string>; // 返回 sid
  resumeSession(sessionId: string): Promise<void>;
  listSessions(): Promise<SessionInfo[]>;

  // Prompt
  submitPrompt(sessionId: string, text: string): Promise<void>;

  // Event stream
  onEvent(cb: (event: HermesEvent) => void): void;
}
```

底层走 `hermes serve` 的 WebSocket JSON-RPC：
- `session.create`（params: cwd/profile）→ 8-hex `sid`
- `prompt.submit`（params: session_id/text）
- `event` stream（token 流 / tool call / 完成）

**关键边界**：HermesSessionClient 只做"接线"，不做任何 session 逻辑。Session 的 create/resume/compression/持久化全部由 Hermes 自己完成。

### 2.3 Situation Chat Runtime Bridge

**定义**：Browser ↔ Fabric ↔ Hermes Session 的桥。

当前链路（要替换的）：

```
Workspace Chatbox → POST /api/chat → 2 × hermes -z one-shot → reply
```

目标链路：

```
Workspace Chatbox（Situation-scoped）
      ↓
Fabric Runtime Bridge（新）
      ↓
HermesSessionClient
      ↓
Hermes serve /api/ws
      ↓
Hermes Session（cwd = FabricAgentWorkspace）
      ↓
event stream 回流到 Chatbox
```

Bridge 职责：
1. 收到 Chatbox 消息 + situationId
2. 确保该 situation 对应一个 Hermes Session（cwd = Fabric Workspace，profile = jd）
3. 转发 prompt 到 HermesSessionClient
4. 把 Hermes event stream 回流到 Browser（SSE 或 WebSocket）

**关键边界**：Bridge 不产生 Memory/Skill，不做 Action execution，不重新实现 session。它只把"人 ↔ Hermes Session"接起来。

## 3. E2E Flow（成功标准）

```
1. 一个全新的 Hermes Profile（~/.hermes/profiles/jd/）被创建
      ↓
2. Fabric 生成 FabricAgentWorkspace（干净 cwd，含 JD World Knowledge）
      ↓
3. 用户在 Workspace 的 Situation Detail 里打开 Situation Chat
      ↓
4. Bridge 调用 HermesSessionClient.session.create(cwd=fabric-workspace, profile=jd)
      ↓
5. 用户发消息"这个商品的流量为什么下降？"
      ↓
6. Hermes Session（cwd 指向 workspace）自主读取 world/jd_shangzhi/metrics.md 等文件
      ↓
7. Hermes 基于 World Knowledge 回答，保持多轮 Session 连续性
      ↓
8. 用户继续追问，Session resume（同一 session_id，历史保留）
      ↓
9. Hermes 产生的 Memory/Skill 只写入 ~/.hermes/profiles/jd/（不进 agentFabric）
```

**成功标准不是"生成了 Markdown"**，而是：
- 新 Profile 的 Session cwd 指向干净 Fabric Workspace ✅
- Hermes 能自主读取 JD World Knowledge ✅
- 多轮 Session 连续性 ✅
- Memory/Skill 只进自己的 Hermes Profile ✅

## 5. 最小 JD Fixture 范围

不是全量 Markdown Projector。只用 P0008.2 的 JD fixture（9 objects + 6 assertions + 1 binding）投影成最小 workspace：

| 文件 | 内容 | 来源 |
|------|------|------|
| `world/jd_shangzhi/system.md` | 京东商智是什么 | WorldModel.system |
| `world/jd_shangzhi/surfaces.md` | 交易概况/流量 | WorldObject (surface) |
| `world/jd_shangzhi/metrics.md` | 成交金额/成交单量/客单价 | WorldObject (metric) |
| `world/jd_shangzhi/dimensions.md` | 时间维度 | WorldObject (dimension) |
| `world/jd_shangzhi/constraints.md` | 数据新鲜度 | WorldObject (constraint) |
| `capability/bindings.md` | 成交金额 ↔ trade.overview | CapabilityBinding |

**全量转换（25 模块/34 Feature/几百指标）是 Builder/Compiler 的事，不是 P0008.4。**

## 7. Success Criteria

1. 新 Hermes Profile 通过 Situation Chat 创建 Session，cwd 指向干净 Fabric Workspace
2. Hermes 能自主读取 JD World Knowledge 文件（filesystem-native，无需 agentFabric 注入 prompt）
3. 多轮 Session 连续性（同一 session_id 历史保留，可 resume）
4. Hermes 产生的 Memory/Skill 只进自己的 Hermes Profile，不进 agentFabric
5. 一条 E2E 链跑通：World → Workspace → Agent ↕ Human → Experience → Memory/Skill
