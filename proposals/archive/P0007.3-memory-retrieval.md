## 1. Problem

P0007.2 generates OperatorMemory records but they are **ephemeral** — computed each time `buildOperatorMemories()` is called and never persisted. There is no mechanism to:

1. **Store** memories across sessions
2. **Retrieve** relevant memories when a new event occurs
3. **Build context** for Hermes to make informed decisions

The gap is not in pattern detection or explanation — those are complete. The gap is in **memory retrieval**: experience exists but is never called upon.

```
OperatorMemory (generated)
      |
      X   ← missing
      |
Operator Context (for Hermes)
```

## 3. Design Decisions

### 3.1 Not Vector Retrieval

**Decision**: Rule-based matching (category + driver + direction), not embedding / vector DB.

**Reasoning**:
- 190 days of data produces ~12 OperatorMemory records
- Embedding-based retrieval is over-engineered at this scale
- Rule-based matching is auditable — every match has a traceable reason
- Can upgrade to vector retrieval later when memory count exceeds ~500

### 3.2 Scored, Not Binary Matching

**Decision**: Each memory gets a similarity score (0-1), not a binary match/no-match.

**Scoring rules**:
| Rule | Score |
|------|-------|
| Same category | +0.60 |
| Same primary_driver | +0.25 |
| Same direction (up/down) | +0.10 |
| Memory confidence scaling | ×memory_confidence |

Scores ≥ 0.3 are returned, sorted by similarity desc.

### 3.3 Context, Not Command

**Decision**: The `OperatorContext` payload is a **suggestion**, not an instruction. Hermes decides what to do.

The context includes a `recommendation` field (e.g., "78% of similar events recovered within 5 days. Monitor before intervening.") but Hermes may override it. Hermes calls agentFabric directly — no CBP transport needed.

### 3.4 Separate Storage from Analysis

**Decision**: `apps/ecommerce/memory/` is a separate module from `apps/ecommerce/analysis/pattern/`.

**Reasoning**:
- `analysis/pattern/` = compute pipeline (stateless, runs on demand)
- `memory/` = persistent store (stateful, accumulates over time)
- Different lifecycles: patterns are ephemeral, memories are durable
- Clean boundary for testing and future replacement

## 4. Data Model

### 4.1 OperatorMemory (Contract)

```typescript
interface OperatorMemory {
  memory_id: string;
  category: 'traffic_driven_drop' | 'conversion_driven_drop' | 'volume_driven_spike' | 'seasonal_pattern' | 'recovery_pattern';
  trigger_signature: {
    primary_driver: string;
    direction: 'up' | 'down';
    season?: string;
  };
  pattern_description: string;
  statistics: {
    observations: number;
    recovery_count: number;
    recovery_probability: number;  // 0-1
    avg_recovery_days: number;
  };
  primary_driver: string;
  driver_confidence: number;       // 0-1
  memory_confidence: number;       // 0-1, grows with log₂(observations)
  last_observed_at: string;
  created_at: string;
}
```

### 4.2 MemoryMatch

```typescript
interface MemoryMatch {
  memory: OperatorMemory;
  similarity_score: number;  // 0-1
  match_reason: string;      // e.g. "same category, same driver"
}
```

### 4.3 OperatorContext (for Hermes)

```typescript
interface OperatorContext {
  type: 'operator_context';
  event: {
    date: string;
    pattern: string;     // "gmv_drop" | "gmv_spike"
    severity: string;    // "low" | "medium" | "high"
  };
  current_metrics: {
    gmv: number;
    orders?: number;
    visitors?: number;
    conversion_rate?: number;
  };
  matched_memories: MemoryMatch[];
  recommendation?: string;
}
```

## 5. SQLite Schema

```sql
CREATE TABLE IF NOT EXISTS operator_memories (
  memory_id TEXT PRIMARY KEY,
  category TEXT NOT NULL,
  trigger_primary_driver TEXT NOT NULL,
  trigger_direction TEXT NOT NULL,
  trigger_season TEXT,
  pattern_description TEXT NOT NULL,
  observations INTEGER NOT NULL DEFAULT 0,
  recovery_count INTEGER NOT NULL DEFAULT 0,
  recovery_probability REAL NOT NULL DEFAULT 0,
  avg_recovery_days REAL NOT NULL DEFAULT 0,
  primary_driver TEXT NOT NULL,
  driver_confidence REAL NOT NULL DEFAULT 0,
  memory_confidence REAL NOT NULL DEFAULT 0,
  last_observed_at TEXT NOT NULL,
  created_at TEXT NOT NULL
);
CREATE INDEX IF NOT EXISTS idx_memories_category ON operator_memories(category);
CREATE INDEX IF NOT EXISTS idx_memories_confidence ON operator_memories(memory_confidence DESC);
```

## 6. API Surface

| Method | Path | Purpose | P |
|--------|------|---------|---|
| `POST` | `/api/memories/sync` | Generate + persist operator memories | P0007.3.1 |
| `GET` | `/api/memories` | List persisted memories | P0007.3.1 |
| `GET` | `/api/context?date=` | Build operator context for Hermes | P0007.3.3 |

### POST /api/memories/sync

Generates OperatorMemory from current signal history, persists to SQLite. Idempotent — re-running updates existing memories (ON CONFLICT upsert).

Response:
```json
{
  "success": true,
  "data": { "stored": 12, "total": 12 }
}
```

### GET /api/context?date=YYYY-MM-DD

Full pipeline: explain event → match memories → build context.

Response:
```json
{
  "success": true,
  "data": {
    "type": "operator_context",
    "event": {
      "date": "2026-05-06",
      "pattern": "gmv_spike",
      "severity": "medium"
    },
    "current_metrics": { "gmv": 9603.75 },
    "matched_memories": [
      {
        "memory": {
          "category": "volume_driven_spike",
          "statistics": { "observations": 4, "recovery_probability": 0.78 }
        },
        "similarity_score": 0.76,
        "match_reason": "same category, same driver, same direction"
      }
    ],
    "recommendation": "Based on 4 similar events, 78% recovered within 5 days. Monitor before intervening."
  }
}
```

## 9. What's NOT Included

| Excluded | Reason |
|----------|--------|
| Vector DB / embedding | Data scale doesn't warrant it (12 memories) |
| Automatic memory learning | No feedback loop yet (needs operator actions) |

| Memory decay / forgetting | Premature — need more data first |
| Cross-entity memories | Single shop only (jd_shop_001) |
| Memory export / sharing | Future concern |

## 10. Future: P0007.4 Feedback Loop

The next step is connecting the loop back:

```
OperatorContext → CBP → Hermes → Decision → Action → Outcome
                                                      ↓
                                              Memory Update
                                              (did recovery happen?)
```

This requires:
1. Action tracking (what did the operator do?)
2. Outcome tracking (did GMV recover?)
3. Memory confidence adjustment based on real outcomes

Currently, memory statistics are based on historical pattern recurrence, not operator action outcomes. P0007.4 would close this loop.
