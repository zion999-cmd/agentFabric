# P0005.3: Discovery Capability Generator

**Status:** Proposed
**Date:** 2026-07-01
**Depends on:** P0005.1 (JD Business Data Connector), P0005.2 (Discovery-Driven Connector Architecture)

---

# Objective

建立 **Discovery → Capability → Connector** 的中间层。

P0005.2 已经解决了 **"发现平台能力"** 的问题。

P0005.3 的职责不是再次 Discovery，而是：

> **消费 Discovery Assets，自动生成 Connector 所需要的能力描述（Capability Blueprint）。**

最终目标：

```
Platform
    │
    ▼
Discovery Runtime
    │
    ▼
Discovery Assets
    │
    ▼
Capability Generator
    │
    ▼
Connector Blueprint
    │
    ▼
Connector
```

Discovery 负责探索。

Capability Generator 负责理解。

Connector 负责运行。

三者完全解耦。

---

# Background

目前已经拥有完整 Discovery 能力。

```
discovery/

    D0002_JD_Capability_Report.md

    jd-capability/

        api_inventory.json

        capability_matrix.json

        indicator_dictionary.json

        business_context_candidates.json

        page_inventory.json

        api-responses/

        screenshots/

        dom/
```

这些资产已经能够描述：

* 平台有哪些 API
* API 返回哪些字段
* 指标含义
* Business Context
* 页面能力
* DOM
* Screenshot
* Capability Matrix

但是：

这些资产仍然属于 Research。

Connector 仍然需要程序员手工维护。

P0005.3 负责把 Research 自动转换成 Capability。

---

# Discovery Package

Capability Generator 不依赖 JD。

它只依赖 Discovery Package。

任何平台只要提供 Discovery Package 即可。

例如：

```
jd-capability/

tmall-capability/

douyin-capability/

amazon-capability/
```

统一输入：

```
Discovery Assets

Required

Capability Report

API Inventory

API Responses

Optional

Indicator Dictionary

Capability Matrix

Business Context Candidates

Page Inventory

DOM Snapshot

Screenshots

Documentation
```

Generator 不关心平台名称。

只消费 Discovery Assets。

# Phase 1 — Capability Discovery

读取：

```
api_inventory.json

capability_matrix.json
```

自动生成：

```
API Modules

Endpoint Groups

Platform Capabilities

Supported Features
```

例如：

```
Transaction

Traffic

Industry

Customer

Marketing

SupplyChain
```

所有能力均来自 Discovery。

程序员不得手写。

---

# Phase 2 — Evidence Analysis

读取：

```
api-responses/
```

自动分析：

每个 API：

* Schema
* 字段类型
* 是否分页
* 是否时间序列
* 是否聚合数据
* Schema Hash

例如：

```
summary.ajax

↓

GMV

Orders

Visitors

Conversion Rate

↓

Transaction Metrics
```

输出：

```
Evidence Blueprint
```

用于后续 Connector。

---

# Phase 3 — Semantic Mapping

读取：

```

Capability Report

Platform Documentation
```

自动建立：

```

↓

Canonical Metric

↓

Business Meaning

↓

Unit

↓

Confidence
```

例如：

```
jdr_sch_trade_deal_ord_ord_amt

↓

gmv

↓

Transaction

↓

currency

↓

0.98
```

新增指标无需修改代码。

根据 Discovery Assets 自动生成：

```

```

```
Acquisition Plan

Parser Plan

Normalizer Plan

Evidence Strategy

Manifest
```

例如：

```

↓

Parser

↓

Evidence

Normalizer

↓

```

Connector 不负责设计。

# Phase 5 — Coverage Analysis

Discovery 与 Connector 的覆盖率。

例如：

```

70 APIs

```

# Design Principles

## 1. Discovery 不负责 Connector

Discovery 只负责发现。

不得生成业务代码。

---

## 2. Capability Generator 不负责采集

Generator 只负责分析 Discovery。

不得访问平台。

---

## 3. Connector 不负责理解平台

Connector 只执行 Blueprint。

不得定义：

* API
* Business Context
* Indicator Mapping

所有能力来自 Generator。

---

## 4. Connector 永远可以重建

只要重新执行：

```
Discovery

↓

Capability Generator
```

即可重新生成 Connector Blueprint。

因此 Connector 永远不是平台知识的唯一来源。
