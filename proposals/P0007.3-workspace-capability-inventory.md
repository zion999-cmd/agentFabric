# P0007.3 — Workspace Capability Inventory & Ownership Audit

**Date**: 2026-08-13
**Type**: Architecture governance — not implementation
**Purpose**: Judge every existing Workspace capability against the new agentFabric/P0007 philosophy. This is a migration-judgment exercise, NOT a "which menu is still unfinished" backlog.

---

## 1. Core Principle

The question is not "which view still needs building", but **"does this capability still have a reason to exist under agentFabric philosophy?"**

```
agentFabric                              HermesAgent (Runtime)
────────────────────────────            ──────────────────────
World Observation                        Reflection
Evidence / Signal                        Memory
Situation                                Memory Retrieval
Agent Activity                           Skill Creation
Human Intervention                       Skill Evolution
Professional Action
Outcome
Learning Context
Provenance / Trust
```

Anything on the left belongs in Domain Workspace. Anything on the right is Runtime-owned and must not appear as a business Workspace capability.

## 3. Judgment Per Capability

### 3.1 Keep / Core

| View | Why it stays | What it is in new architecture |
|------|-------------|-------------------------------|
| Situation Feed | This IS the primary business interface | Situation = 中心对象 |
| Situation Detail | 5-layer: 发生了什么 → Agent 理解 → 建议 → 处理 → 追问 | Situation Workspace |

这两个是 P0007.3 的主干。京东运营人员的"今日工作"就是 Situation Feed。

### 3.2 Keep (business observation)

| View | Why it stays | Notes |
|------|-------------|-------|
| 商品分析 | 商品维度经营观察 | 不是 Chat，是商品维度的 Observation |
| 趋势观察 | 信号变化时间轴 | 经营观察的一部分 |

这两个是"经营观察"section 的正当成员。它们是 Situation 的补充维度，不是独立产品能力。

### 3.3 Keep / Secondary (advanced)

| View | Why secondary | Where |
|------|--------------|-------|
| Evidence Viewer | 信任追溯，非日常主界面 | 系统 → Evidence |
| Capability Explorer | 技术能力清单，非业务语言 | 系统 → Capability |
| Agent Runtime | 执行历史 + Replay | 系统 → Agent Runtime |

这三个正确降级到"系统"区。业务人员不从 Capability 开始工作。

### 3.4 Evaluate / Migrate

| View | 旧含义 | 新架构判断 |
|------|--------|-----------|
| Inbox (今日发现/增长/风险/审核) | AI Findings + Review queue | 这些"发现"本质上是 Situation 的前身。今日发现→Situation Feed；审核中心→Intervention。**迁移，不是保留两个并列入口** |
| Decision Panel (决策依据) | Agent reasoning 展示 | 部分成为 Evidence Drawer，部分成为 Intervention Surface。**迁移** |

关键判断：Inbox 的"AI 发现"和 Situation 是同一个东西的两个名字。旧代码用 Finding/Review，新代码用 Situation/Intervention。不能两者并列——否则业务人员面对两个入口做同一件事。

### 3.5 Hide / Remove

| View | Why remove | Action |
|------|-----------|--------|
| Memory 成长 | Memory 属于 Hermes Runtime。agentFabric 不管理 Memory | 从主动 nav 隐藏 |

这不是"待实现"。这是**架构上就不该存在**。旧代码的 Memory 是 agentCMS 自己造的 Memory Engine，P0007 已经明确这个职责归 Runtime。

### 3.6 Decompose

| View | Mixed content | 分解 |
|------|--------------|------|
| Agent 配置 | Memory TTL/decay/threshold + LLM provider/model/temperature + ranking weights | Memory 设置 → Runtime（隐藏）；LLM 配置 → Runtime（隐藏）；ranking weights → 可能保留为业务策略（P0007.5 Trust/Policy） |

Agent 配置里唯一可能属于 agentFabric 的是 ranking weights——那是业务策略，不是 Memory/LLM 管理。

### 3.7 Secondary (Runtime visibility)

| View | 判断 |
|------|------|
| Agent Session (旧) | 偏技术/Runtime：Execution Events、Task lifecycle、Capability invocation。不是 Domain Workspace 核心。保留在系统区作为 Runtime visibility，但不要为运营人员补"大聊天 Agent Session" |

### 3.8 P0007.3 TODO

| View | 判断 |
|------|------|
| Situation-scoped Chat | P0007.3 明确定义：Chat 不是独立主界面，是 Situation 上下文中的补充交互。当前只有壳，无真实能力。**这是 P0007.3 的正经 TODO，不是"Phase 3 未实现"** |

## 4. What This Changes

### 4.1 Immediate navigation cleanup

```
今日工作
├── 全部 Situation       ✅ Keep
├── 待我处理             ✅ Keep
├── Agent 处理中          ✅ Keep
└── 已处理               ✅ Keep

经营观察
├── 商品                 ✅ Keep
├── 趋势                 ✅ Keep
└── 历史归档             ⚠️ Evaluate — 可能并入经营观察

系统
├── Agent Runtime        ✅ Keep (secondary)
├── Evidence             ✅ Keep (secondary)
└── Capability           ✅ Keep (secondary)

Legacy (hidden)
├── Inbox (旧)           → 迁移到 Situation Feed，不是保留
├── Memory (旧)          → 移除（Runtime-owned）
├── Agent 配置 (旧)      → 分解（ranking weights 可能保留，其余移除）
└── Agent Session (旧)   → 降级到系统区 Runtime visibility
```

### 4.2 The real backlog (not "unimplemented menus")

1. **Situation-scoped Chat** — P0007.3 的正经 TODO
2. **Inbox → Situation 迁移** — 把旧 Finding/Review 数据映射到 Situation/Intervention
3. **Decision Panel → Evidence Drawer 迁移** — 决策依据变成证据抽屉
4. **Agent 配置分解** — ranking weights 保留为业务策略，Memory/LLM 移除
5. **Memory 成长移除** — 从主动 nav 隐藏

---

## 5. Success Criteria for This Audit

- [ ] Memory 成长 / Memory TTL / Memory decay / LLM config 不再作为业务 Workspace 能力出现
- [ ] Inbox 和 Situation Feed 不再是两个并列入口（迁移）
- [ ] Decision Panel 不再叫"决策依据"，成为 Evidence Drawer 或 Intervention Surface
- [ ] Agent Session 不再作为业务人员主界面（降级到系统区）
- [ ] Situation-scoped Chat 被明确标记为 P0007.3 TODO（不是 Phase 3）
- [ ] 每个 view 都有明确的 new-architecture ownership，不再是"已实现/未实现"二维状态
