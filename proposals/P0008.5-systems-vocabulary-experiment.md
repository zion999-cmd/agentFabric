# P0008.5 Controlled Experiment — `world/` vs `systems/`

**Date**: 2026-08-14
**Type**: Controlled vocabulary experiment

---

## 1. 实验设计

- 唯一变量：Runtime-facing 目录命名 `world/` → `systems/`（含 re-nest：primitives 归入 `systems/jd-shangzhi/`）
- AGENTS.md 只做术语同步（`world/` → `systems/`），**不加行为性指令**
- 3 个 known-fact prompt 完全不变
- 新 blank profile（p00085sys），无 JD soul/memory/skill/session history
- 事实内容不变（已验证 4.6 / 同行同级 / 10 modules 仍在，导航 INDEX 无泄露）

## 4. 结果：Case C — 部分提升（1/3）

- Fact 1：**0 → 1 提升**（Agent search_files + read_file 找到 systems/jd-shangzhi/INDEX.md，正确回答 4.6 + 祁门红茶官方旗舰店 + 11855009）
- Fact 2：无变化（仍 web_search）
- Fact 3：无变化（仍 web_search）

---

## 5. 解读

### Fact 1 为何提升

"店铺星级"问题对应 **system identity**（店铺信息），Agent 通过 search_files 找到了 `systems/jd-shangzhi/INDEX.md`（系统档案），read_file 得到 4.6。

`systems/` 命名 + `jd-shangzhi/` 子目录让"系统档案"更自然——Agent 对"系统是什么/店铺是谁"类问题更容易联想到读 systems/。

### Fact 2/3 为何仍失败

- Fact 2（对比基准）→ dimensions/index.md
- Fact 3（导航模块）→ jd-shangzhi/INDEX.md 的 "Top-Level Navigation"

这两个仍是 **lookup/枚举类问题**，Agent 默认走 web_search，没有"先查本地 systems/"的信号。

---

## 6. 结论

> `systems/` 比 `world/` 更符合模型语义，**对 system identity 类问题**（店铺是谁、星级多少）有提升（1/3）。

但**不足以覆盖所有 World 消费场景**（维度/指标/导航枚举类问题仍走 web_search）。

这是 **Case C（部分提升）**，不是 Case A（明显提升）。

---

## 7. 组合假设（供 Review，不实现）

综合本轮 + 上轮（World Map A/B）结果：

| 变量 | 效果 |
|------|------|
| `world/` → `systems/` 命名 | 部分提升（system identity 类问题 0→1） |
| `world/INDEX.md` 导航 | 无效（Agent 不读，因缺"读 INDEX"指引） |

**两个变量都未能独立解决 World 消费**。可能的下一轮：`systems/` 命名 + AGENTS.md 显式 "读 systems/INDEX.md" 指引 的组合。

但本轮按 NOT Included，不做组合，停止等待 Review。
