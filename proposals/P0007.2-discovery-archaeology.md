## 2. What's LEGACY Assumption

### 2.1 `approve/reject/modify` as Complete Professional Action Model

**Problem**: Human decision is compressed into 3 actions. P0007.2's architecture defines:

```
Human Intervention:
├── Decision (accept/reject/modify/defer/no_action)
├── Correction
├── Annotation
├── Context Supplement
├── Action Intent
└── Professional Action
```

The old model only captures `Decision` (and `modify` with unstructured `modified_output`). It completely misses Correction, Annotation, Context Supplement, and Professional Action.

### 2.2 `reason_category` as Pre-Defined Enum

**Problem**: The 10 categories are hardcoded. A real operator might reject a ranking because:
- "The supplier just called and told us their factory is down for maintenance until next week"
- "We're about to sign an exclusive deal with this brand, so rankings will change"
- "This product is being recalled"

None of these fit the 10-category enum. Real operational knowledge doesn't fit a fixed category system.

### 2.3 `MEMORY_PATTERN_RULES` — Pre-Written, Never Validated

**Problem**: All 10 rules have `support_count: 0, total_related: 0`. They were written as hypotheses, never validated against real operator behavior. The extraction pipeline (`extractMemories`) can produce memories, but it only operates on `action=reject` reviews with a matching `reason_category`. If no operator ever uses those categories, no memory is ever created.

### 2.4 `Feedback.business_result` — Manual Attribution

**Problem**: The `metric_delta`, `baseline`, `post_value` fields assume a human can attribute business outcomes to their actions. Real operators rarely fill in "GMV changed by +15% because I modified this ranking." This data only exists if someone explicitly enters it.

### 2.5 `modified_output: Record<string, unknown>` — Unstructured

**Problem**: When a human modifies an agent output, the modification is stored as opaque JSON. There's no structure to capture "what field was changed, from what to what, and why." This loses the semantic richness of the intervention.

## 3. What's MISSING — Completely Unobservable

### 3.1 Professional Action Execution

**Missing**: When an operator takes an action in the real world (changes a price, updates a listing, contacts a supplier), there's NO code to observe that action.

| Missing | Why it matters |
|---------|---------------|
| Action observation mechanism | Can't record what happened |
| Action type vocabulary | Don't know what kinds of actions exist |
| Action → system linkage | Can't verify action was executed |
| Action → World Change mapping | Can't track consequences |

### 3.2 Non-Decision Interventions

**Missing**: The code has no concept of:
- **Correction**: "The data shows visitors=23 but I know we had 50 people in-store today"
- **Annotation**: "This product is seasonal tea — ignore January summer metrics"
- **Context Supplement**: "We changed our packaging on Aug 5, so metrics before that are misleading"
- **Action Intent without Action**: "I would lower the price but need manager approval first"

### 3.3 Outcome Observation

**Missing**: No code exists to re-observe the world after an action and record the outcome. The `Feedback.business_result` field exists but requires manual entry. P0007.4's vision of automatic re-observation via JD Capability is not implemented.

### 3.4 Task/Stage/Recovery Model

**Missing**: No code tracks whether an Agent task went through stages, failed and recovered, or required human takeover. The `taskId` reference exists but there's no execution lifecycle model beyond "started → completed."

### 3.5 Action Vocabulary

**Missing**: No domain-specific action types are defined anywhere. The codebase has zero concept of:
- Price changes
- Listing updates
- Inventory restocking
- Campaign adjustments
- Supplier communications
- Content changes

These are the real actions operators take, and the codebase has no vocabulary for them.

## 5. Runtime Gaps — Schema Exists, Behavior Missing

### 5.1 Review Lifecycle — Broken

`ReviewEvent.status` lifecycle is incomplete:
- `POST /api/reviews` sets `status: 'pending'`
- **No code path** transitions to `'approved'`, `'rejected'`, or `'modified'`
- Reviews stay "pending" forever

### 5.2 Feedback — No HTTP Route

Full pipeline exists (schema + `buildFeedback()` + `storeFeedback()`) but:
- **No `POST /api/feedback` route** — feedback is unreachable from Workspace
- `ReviewFacade.recordFeedback()` is wired but not exposed

### 5.3 Knowledge Promotion — No Trigger

`autoPromote()` exists but **no HTTP route** to trigger it. Knowledge promotion is dead code from the HTTP layer.

### 5.4 Memory Override — Schema Only

`MemoryOverride` schema defines `is_overridden`, `override_reason`, `overridden_by`, `overridden_at`. But:
- `extractMemories()` always sets `is_overridden: false`
- No code path sets a memory as overridden
- Operators cannot deprecate auto-extracted memories

### 5.5 Human-in-the-Loop Skill — Missing

`SkillHandlerType`: `'kernel' | 'orchestrator' | 'facade'`. **No `'review'` handler type.** Human review actions (approve/reject/modify) cannot be dispatched through the chat/skill system.

### 5.6 Learning Context — Schema Only

`LearningContextSchema` exists (P0007.1) but no repository, no route, no builder creates `LearningContext` records.

|--------------|----------|-------|
| `ReviewAction` ('approve','reject','modify') | `HumanIntervention.type: Decision` — subset only | Keep as one type among many |

## 6. What NOT to Carry Forward

| Legacy Artifact | Why NOT |
|----------------|---------|
| `MEMORY_PATTERN_RULES` | Pre-written rules, zero real data validation |
| `reason_category` enum | Fixed categories don't capture real operational knowledge |
| `extractMemories()` pipeline | Reject-count-based heuristics, not observation-based |
| `approve/reject/modify` as complete action model | Only covers Decision, not the full Intervention grammar |
| `modified_output: Record<string, unknown>` | Unstructured — loses semantic richness |
| Manual `business_result` attribution | Requires humans to fill in outcomes — should be auto-observed |
