# P0008.1 — Contract Archaeology & Minimal JD World Model: Gap Map

**Date**: 2026-08-13
**Type**: Read-only archaeology — no implementation
**Inputs**: `discovery/`, `data/jd_shangzhi_features/`, `WorldExplorationTask/`, Capability/Evidence contracts

---

## 1. 三组 Discovery 资产分别包含什么？

### A. `discovery/`（Claude guided，2026-06-30，D0002）

**Ontology**: Page (Surface) → Endpoint → JDR Indicator (Metric) + Business Context overlay + API↔Page graph

| 资产 | 结构 | 建模了什么 primitive |
|------|------|---------------------|
| `page_inventory.json` | 15 pages, each `{page, url, status, screenshot, dom, apis[]}` | **Surface**（强）+ HTTP evidence |
| `capability_matrix.json` | page → endpoint 矩阵 | Surface + Relationship（窄：page↔API） |
| `api_inventory.json` | endpoint → dot-path field schema | 原始字段字典（无语义） |
| `indicator_dictionary*.json` | jd_key → inferred_name / category / occurrence | **Metric**（三层：raw→inferred→verified） |
| `business_context_candidates.json` | endpoint → context-name candidates | 松散 Concept 候选 |
| `D0002_JD_Capability_Report.json` | api_modules + verified_business_contexts + api_relationship_graph | System(弱) + Capability(=Business Context) + Relationship |

**核心缺陷**：语义承载层 `verified_business_contexts`（field+unit+verified）只存在于人工产出的报告 JSON 里，不是机器可查询 schema。机器可查询的 `api_inventory` / `indicator_dictionary` 停在 opaque `jdr_*` key 和 dot-path。

### B. `data/jd_shangzhi_features/`（Claude 早期 agentCMS）

**Ontology**: page map + feature catalog + metric dictionary（三层，非 typed graph）

| 资产 | 结构 | 建模了什么 primitive |
|------|------|---------------------|
| `toc_navigation.json` | 16 nav items `{text, href}` | Surface（page map） |
| `all_nav_links.json` | 26 links | Surface + System 入口 |
| `功能介绍_all_categories.json` | 34 features, `{code, text}` | **Capability**（最结构化的一层） |
| `指标说明_all_categories.json` | 25 modules，值 = 原始文本 | **Metric**（未解析，但最丰富） |
| `sidebar_tree.json` | 空（失败） | — |

**核心缺陷**：metric 定义（`名称（模块-子模块）：定义` 模式，含 formula + constraint）存成巨型字符串，从未解析成 `{name, scope, formula}` 对象。最值钱的三层菜单树（资费说明.txt）也是扁平文本。

### C. `WorldExplorationTask/`（Hermes zero-shot，2026-08-13）

**Ontology**: typed World Model + page map + raw bodyText

| 资产 | 结构 | 建模了什么 primitive |
|------|------|---------------------|
| `jdsz_world_discovery.json` | metadata / navigation_structure / core_metrics / time_dimensions / comparison_types / api_endpoints_**suspected** / technical_notes | System + Surface + Metric + Dimension + Constraint + Capability(**带 epistemic 标记**) |
| `jdsz_all_pages.json` | page → `{title, url, bodyText, navItems[], metrics[](空), charts[]}` | Surface + raw bodyText |
| `jdsz_complete_data.json` | 同上 + 更全 | Surface + raw |
| 18 screenshots | 每页截图 | Evidence |

**关键发现**：Hermes 在**零 schema** 前提下，独立产出了 System/Surface/Metric/Dimension/Constraint/Capability 全套 primitive，且用 `api_endpoints_suspected` 命名天然表达了 epistemic 区分（suspected vs observed）。

## 2. Claude 历史探索与 Hermes 新探索共同发现的结构？

三方**共同**自然产出的结构（收敛点）：

| 结构 | Claude discovery/ | Claude features/ | Hermes zero-shot |
|------|-------------------|------------------|------------------|
| **System**（京东商智作为系统） | partial (`api_modules`) | implicit | ✅ explicit (`metadata.system_name`) |
| **Surface**（页面/模块） | ✅ page/url | ✅ toc/nav | ✅ navigation_structure |
| **Metric**（指标） | ✅ jdr_key 三层 | ✅ 指标说明（raw） | ✅ core_metrics |
| **Dimension**（维度） | partial (field prefix) | implicit (prose) | ✅ time_dimensions + comparison_types |
| **Constraint**（约束） | ad-hoc status | implicit (prose) | partial (data_freshness, export formats) |
| **Capability**（能力） | ✅ Business Context | ✅ feature catalog | partial (api_endpoints) |

**三方都围绕"页面 + 指标 + 能力"这三个核心概念**，即使没有统一 schema。

## 4. 哪些是 verified fact？

**Verified（有真实 evidence 支撑）**：
- 页面 URL 结构（三组资产一致，15 页 / 10 模块 / 16 模块 交叉验证）
- 核心指标名称（GMV/成交金额、成交单量、成交客户数、客单价、店铺浏览量、访客数、转化率——三方一致）
- 时间维度（实时/昨天/近7天/近30天/天/周/月——三方一致）
- 对比维度（环比/同比/同行同级均值——三方一致）
- 真实 metric 值（WorldTask bodyText 里的 ¥7,983.16 等，来自真实 CDP 采集）

## 5. 哪些只是 suspected / inferred？

**Suspected（推测，无 evidence）**：
- `api_endpoints_suspected[]`（Hermes 猜测的 /szweb/api/* 端点——实际上 JD 用 szgateway.jd.com，Hermes 猜错了路径！）
- `indicator_dictionary.json` 里 `verified: false` 的 inferred_name
- 34 feature 的 `code` slug（有拼写错误：dealAnalysiss, customerAnalysiss——推测生成的英文名）

**关键教训**：Hermes 的 `api_endpoints_suspected` 猜错了（szweb/api 而非 szgateway.jd.com），但它的 epistemic 标记是对的——它**知道**这些是猜测。

## 6. 当前 Evidence 能否支持 World Fact provenance？

**部分支持，但语义不匹配。**

当前 `EvidenceMetadata`：
```
source, shop_id, data_type, acquired_at, acquisition_method, processing_method, content_hash
```

- ✅ 有 `source`（platform）、`content_hash`（tamper detection）、`acquired_at`、`acquisition_method`
- ❌ `data_type` 是自由字符串（summary/trend/productTop），没有 World Fact evidence 类型（screenshot/DOM/network_response/api_schema/documentation）
- ❌ `shop_id` 强绑定"店铺数据采集"，World Discovery evidence 不是 shop-scoped
- ❌ 没有 `discoveredBy`（explorer session）、`sourceSurface`（哪个页面发现的）、`epistemic_status`

**结论**：Evidence 支持"业务数据 provenance"（GMV=¥337 来自 CDP），但**不支持"World Fact provenance"**（"JD 有 transaction_amount 这个指标"这一事实需要 screenshot/DOM 作为 evidence）。

## 7. 当前 Capability 能否与 World Knowledge 建立 binding？

**部分能。**

当前 `CapabilityContractEntry`：
```
capability, domain, name, description, intent, inputs, outputs[], metrics[], dimensions[], provider, validation, constraints
```

- ✅ `metrics[]` 有 canonical name + unit + verified — 可 binding 到 World Metric
- ✅ `provider.platform` — 可 binding 到 World System
- ✅ `validation.status` — 已有 epistemic 语义（verified/captured/content_only/pending）
- ❌ 没有 `surface`（capability 不知道自己在哪个页面）
- ❌ 没有 `entity`（capability 不知道它 measure 哪个实体）
- ❌ `domain` 是自由字符串（trade/traffic），不是 World Concept 的一等引用

**结论**：Capability 已经有 60% 的 World binding 所需字段，缺 Surface/Entity 引用。P0008.2 需要的是"补齐 binding"，不是"重构 Capability"。

## 8. 当前代码是否已有类似 World Model 的 contract？

**没有独立的 WorldModel schema。** World primitives 散落在 4 个 schema：

| primitive | 现有位置 | 形态 |
|-----------|---------|------|
| System | `Capability.provider.platform` | 自由字符串 |
| Metric | `Capability.metrics[]`（canonical/unit/confidence/verified） | 最接近 |
| Dimension | `Capability.dimensions[]` | 自由字符串数组 |
| Constraint | `Capability.constraints` | 已有（premium/ad_account/popup） |
| Entity | `Signal.entity_type`（硬编码 enum）+ `Situation.entity`（自由形式） | 松散 |
| Surface | 无 | — |
| Concept | 无（`domain` 是弱代理） | — |
| Relationship | 无 | — |

**避免重复建设**：Metric/Dimension/Constraint 的形态已在 Capability Contract 里。World Model 不需要重新发明这些——需要的是把它们从"capability 属性"提升为"世界一等实体"，并补上 Surface/Entity/Concept/Relationship。

## 9. 建议的 Minimal World Model primitives

从三组真实资产反推（**不强行套 9 个 primitive，只保留有真实证据支撑的**）：

```
System          — 京东商智作为被探索系统（三方都有）
Surface         — 页面/模块（三方最强的一致结构）
Metric          — 指标（三方核心，但需要统一三层）
Dimension       — 时间/渠道/对比维度（三方一致）
Constraint      — 数据新鲜度/导出格式/付费墙（WorldTask 有，features 有资费）
Capability      — 可观察能力（discovery 的 Business Context + features 的 feature catalog）
Relationship    — metric 属于哪个 surface；metric 关联哪个 entity（discovery 有 API↔Page 边）
```

**暂不引入（无足够证据）**：
- `Entity` — 三方都只隐式出现，从未一等建模。Entity registry 是 P0008 后续阶段的风险点，不是 P0008.1 必须。
- `Concept` — discovery 有 Business Context 候选，但太松散。可作为 Relationship 的属性，不独立。

**关键修正**：原 P0008 提案列了 9 个 candidate primitive（System/Surface/Entity/Concept/Metric/Dimension/Constraint/Capability/Relationship），但三组资产实际只稳定支持 7 个（去掉 Entity + Concept 独立节点，因为无真实证据）。这是"不为符合 9 个 primitive 强行修改真实资产"的直接结果。

## 10. 支持这些 primitives，现有基础设施真正缺什么？

| 缺口 | 严重度 | 说明 |
|------|--------|------|
| **World Fact epistemic status** | 🔴 高 | 现有只有 `verified: boolean`，需升级为 `suspected/observed/verified`。Hermes 实验证明 Agent 天然区分，但 contract 没收 |
| **World Fact provenance** | 🔴 高 | Evidence 不支持 screenshot/DOM/network_response/api_schema/documentation 类型的 World evidence，无 `discoveredBy`/`sourceSurface` |
| **Surface 一等实体** | 🟡 中 | 页面目前只是 `page` 字符串，无 registry。Capability 无法 binding 到具体 surface |
| **Entity registry** | 🟡 中 | 三方都隐式，无一等。但 P0008.1 可延后 |
| **World Model Registry** | 🟡 中 | 需要类似 CapabilityRegistry 的查询接口（World Query） |
| **Capability ↔ Surface/Entity binding** | 🟡 中 | Capability 缺 surface/entity 引用 |
| **Metric 三层统一** | 🟢 低 | discovery 已有三层（raw→inferred→verified），但未成 schema |
| **Discovery Artifact 交付协议** | 🟢 低 | Explorer 交付物格式不统一（P0008.5 的事） |

## 结论：Gap Map 摘要

```
已有（不重复建设）:
  Metric/Dimension/Constraint 形态（在 Capability Contract）
  Evidence 的 content_hash / acquisition_method（provenance 骨架）
  Registry 模式（CapabilityRegistry 可复用为 World Query 模式）

真正缺（P0008.1 需定义）:
  1. World Fact epistemic status（suspected/observed/verified）
  2. World Fact provenance（screenshot/DOM/network as evidence type）
  3. Surface 一等实体（页面 registry）
  4. Capability ↔ Surface/Entity binding

可以延后（无足够证据）:
  Entity registry（三方都隐式）
  Concept 独立节点
  Pricing/资费建模
```

**最大发现**：三组资产中，Hermes zero-shot 的 `jdsz_world_discovery.json` 最接近 World Model——它在零 schema 下独立产出了 System/Surface/Metric/Dimension/Constraint/Capability 全套，且用 `_suspected` 后缀天然表达了 epistemic 区分。这证明 P0008 的 World Model Contract 应该**从 Hermes 的自然产出反推**，而不是从 Claude guided discovery 的扁平 Page→Endpoint→Indicator 结构反推。
