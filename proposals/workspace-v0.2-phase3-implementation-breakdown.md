## Phase 3.1 — Runtime Kernel Contract

### Goal

定义 Runtime Kernel 的标准化 ExecutionRequest / ExecutionEvent 契约。不修改 Kernel 内部逻辑——只定义外层契约。

### Scope

```
Define:
├── ExecutionRequest schema
│   ├── capabilityId (from Contract)
│   ├── provider (platform + acquisition)
│   ├── parameters (date_range, shop_id)
│   └── taskId (generated by gateway)
│
└── ExecutionEvent schema
    ├── intent.resolved
    ├── capability.selected
    ├── execution.started
    ├── acquisition.started
    ├── acquisition.progress
    ├── evidence.created
    ├── execution.completed
    ├── response.ready
    └── error
```

### Files

| File | Change | Purpose |
|------|--------|---------|
| `shared/schemas/execution.ts` | **NEW** | ExecutionRequest + ExecutionEvent Zod schemas |
| `apps/ecommerce/runtime/kernel/types.ts` | **Modify** | Add capability-aware execution types |
| `tests/contract/execution.contract.ts` | **NEW** | Contract tests for event schema validation |

### NOT in 3.1
- ❌ Kernel implementation changes
- ❌ Event emission from Kernel
- ❌ SSE streaming

## Phase 3.2 — HermesAgent Capability Discovery

### Goal

HermesAgent 可以调用 `CapabilityRegistry.searchByIntent()` 并根据返回的候选能力做出选择。

### Scope

```
Implement:
├── HermesAgent → CapabilityRegistry bridge
│   ├── Load contract on agent init
│   ├── searchByIntent() integration
│   └── Capability selection logic
│
├── Capability selection → execution plan
│   ├── Map capability to connector
│   ├── Resolve acquisition parameters
│   └── Build ExecutionRequest
│
└── HermesAgent tool: `discover_capability`
    ├── Wraps searchByIntent as a callable tool
    └── Returns capability candidates to HermesAgent
```

### Files

| File | Change | Purpose |
|------|--------|---------|
| `platform/runtime/hermes/capability-bridge.ts` | **NEW** | HermesAgent ↔ CapabilityRegistry adapter |
| `platform/runtime/hermes/tools.ts` | **Modify** | Add `discover_capability` tool definition |
| `platform/server/routes/runtime.ts` | **Modify** | Add `POST /api/runtime/chat` (accepts prompt, delegates to Hermes) |

### NOT in 3.2
- ❌ Runtime Kernel execution
- ❌ Event emission
- ❌ Workspace UI updates

## Phase 3.3 — Workspace Event Binding

### Goal

Agent Session UI 从 static shell 升级为实时消费事件流。Phase 2 的 event slots 从 placeholder 变为真实数据。

### Scope

```
Implement:
├── Event consumption in Agent Session
│   ├── SSE connection to /api/runtime/chat/{taskId}/events
│   ├── Event → Agent Activity slot mapping
│   └── Event timestamp + order display
│
├── UI state transitions
│   ├── idle → task submitted → acquiring → done
│   ├── Enable input (remove Phase 2 disabled state)
│   └── Error state rendering
│
└── Response rendering
    ├── Agent response text
    ├── Capability badge (click → Contract Explorer)
    └── Evidence links (click → Evidence Viewer)
```

### Files

| File | Change | Purpose |
|------|--------|---------|
| `workspace/app.js` | **Modify** | loadAgentSession → enable input + wire SSE + event handlers |
| `workspace/index.html` | **Modify** | Remove input disabled attribute + notice visibility toggle |
| `workspace/styles.css` | **Modify** | Event slot states: pending → active → completed |
| `platform/server/routes/runtime.ts` | **Add** | `GET /api/runtime/chat/{taskId}/events` (SSE) |

### NOT in 3.3
- ❌ Multi-turn conversation
- ❌ Session history UI
- ❌ Real-time WebSocket

## Phase 3.4 — First End-to-End Capability

### Goal

一个完整的 capability（traffic.overview）从头到尾跑通：prompt → capability → acquisition → evidence → response。

### Scope

```
Verify end-to-end:
├── User types "分析流量下降原因" in Agent Session
├── HermesAgent calls searchByIntent → selects traffic.overview
├── Runtime Kernel executes CDP acquisition
├── Events stream to Agent Session UI
├── Evidence Viewer shows provenance chain
└── Agent response displayed with capability badge + evidence links
```

### Verification

| Step | Check |
|------|-------|
| POST /api/runtime/chat | Returns taskId with status "accepted" |
| SSE event stream | All 8 event types emitted in order |
| Agent Activity panel | All events rendered correctly |
| Evidence files | Stored with correct provenance metadata |
| Evidence Viewer | Provenance chain renders on click |
| Agent response | Text + capability badge + evidence links |
| Phase 2 views | Inbox/Product/Trend/Archive/Memory/Runtime unchanged |

### NOT in 3.4
- ❌ Other capabilities (only traffic.overview)
- ❌ Multi-capability chaining
- ❌ Performance optimization
