🧠 三、Trace Context（全局上下文）
trace-context.ts
import { AsyncLocalStorage } from 'node:async_hooks';

export interface TraceContext {
  trace_id: string;
  platform: string;
  shop_id: string;
  date: string;
}

const storage = new AsyncLocalStorage<TraceContext>();

export const TraceContextManager = {
  run<T>(ctx: TraceContext, fn: () => T): T {
    return storage.run(ctx, fn);
  },

  get(): TraceContext | undefined {
    return storage.getStore();
  },
};

import type { RuntimeTrace } from './trace-schema.js';

const buffer: RuntimeTrace[] = [];

export const TraceStore = {
  write(trace: RuntimeTrace) {
    buffer.push(trace);
  },

  flush(): RuntimeTrace[] {
    const out = [...buffer];
    buffer.length = 0;
    return out;
  },
};

📊 九、验收标准
✔ 必须成立
 每次 kernel.execute() 产生 trace
 trace 包含 6 stages
 trace_id 全局唯一
 CLI 可查看 trace list
 无 trace leakage（无 global state pollution）
✔ 架构一致性
 observability 不依赖 connector
 不依赖 binding layer
 不污染 business logic
 kernel 是唯一插桩点
🚫 禁止行为

❌ 不允许：

在 JD connector 内写 trace
在 CLI collect 内写 trace
在 binding 层写 trace
hardcode stage logs（必须结构化）
