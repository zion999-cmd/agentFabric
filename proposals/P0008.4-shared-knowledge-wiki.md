# P0008.4 — Shared Knowledge Wiki

**Date**: 2026-08-13
**Depends on**: P0008.1 / P0008.2 / P0008.3
**Type**: Design Proposal — no implementation

---

## 1. Objective

agentFabric 给 Runtime 的知识不能只有 World Knowledge。除了京东商智/ERP/CMS 等系统的 World Model，业务 Agent 还需要读取：

- 平台规则
- 新推广方式
- 营销案例
- 行业资料
- 企业 SOP
- 品牌规范
- 组织知识
- 外部研究资料

这些属于 **Shared Knowledge**，不属于 World Model / Learning Context / Hermes Memory-Skill-Soul。

P0008.4 定义 Shared Knowledge 的最小组织机制：Raw Sources → LLM-maintained Wiki → Governance，使多个 Runtime Session 能共享、复用、演进同一份业务知识，而不是每个 Session 各自从原始材料重新推导。

参考 Andrej Karpathy 的 LLM Wiki 模式：

```
Raw Sources → LLM-maintained Wiki → Schema/Rules
```

---

## 2. Architecture

### 2.1 核心原则

1. **Raw source immutable** — 原始来源只读，永不改写
2. **Wiki is persistent and compounding** — 知识积累，不重建
3. **LLM maintains** summaries / cross-references / contradictions / indexes
4. **Schema/Rules govern** structure and workflow
5. **Query reads existing Wiki**，不是每次从 raw 重新推导
6. **index.md** 是主导航入口
7. **log.md** 记录 wiki 演进历史
8. **No RAG/vector search**，直到规模证明必要

### 2.2 四层知识严格分离

| 层 | 回答 | 归属 |
|----|------|------|
| `world/` | "这个世界本身是什么" | Fabric（P0008.2 World Model） |
| `knowledge/wiki/` | "人类已经提供了哪些共享知识" | Fabric（P0008.4 Shared Knowledge） |
| P0007 Learning Context | "真实工作过程中发生过什么" | Fabric（P0007） |
| Hermes Memory / Skill | "Runtime 从 Experience 中学会了什么" | Hermes Profile |

**这四层绝不合并。**

## 3. Ownership

```
Fabric Agent Workspace
├── world/          — P0008.2 World Model projection
│                    Fabric-owned, verified/assertion/evidence 语义
│
└── knowledge/      — Shared Knowledge
    ├── raw/        — 人类/外部提供的源材料（immutable）
    ├── wiki/       — Runtime 维护的 Markdown 知识（跨 Session 共享）
    ├── KNOWLEDGE.md — 治理规则（governance，非业务知识）
    ├── index.md    — 内容导向导航
    └── log.md      — append-only 操作历史

Hermes Profile（agentFabric 之外）
├── SOUL
├── Memory
├── Skills
├── Sessions
└── Plans
```

**Hermes Profile 保持在 agentFabric Shared Knowledge ownership 之外。**

---

## 4. Lifecycle

```
Raw Source (immutable)
      ↓ Ingest
Wiki Page (persistent, compounding)
      ↓ LLM maintenance
Summaries / Cross-references / Contradictions / Indexes
      ↓ Query
Answer (reads existing Wiki, not re-derive from raw)
      ↓ Lint
Contradictions / Stale pages / Orphan pages / Missing cross-refs / Gaps
```

- Wiki 页面一旦创建就持久化，后续 ingest 更新已有页面而非无脑新建
- 每次操作（ingest/query/lint）append 到 log.md
- index.md 随内容演进更新

## 5. Directory Structure

```
knowledge/
├── KNOWLEDGE.md          ← 治理规则（governance，不是业务知识）
├── index.md              ← 内容导向导航（主入口）
├── log.md                ← append-only 操作历史
├── raw/
│   ├── platform/jd-商智-推广规则.pdf
│   ├── marketing/双11-大促案例.md
│   └── org/客服-SOP.md
└── wiki/
    ├── jd-推广规则.md     ← 从 raw 提取/总结，含 source 引用
    ├── 双11-大促案例.md
    ├── 客服-SOP.md
    └── 行业-品牌规范.md
```

**只定义最小结构，不建知识管理平台。**

---

## 6. KNOWLEDGE.md Responsibilities

KNOWLEDGE.md 是 **governance**，不是业务知识。它告诉 Runtime：

1. `raw/` 是只读源材料，永不改写
2. 如何分类知识（domain/tags）
3. 如何创建/更新 Wiki 页面
4. 何时更新已有页面而非新建重复页面
5. 如何维护交叉链接
6. 如何保留 source/provenance
7. 如何表示 uncertainty / contradiction（不静默消解分歧）
8. 如何更新 index.md
9. 如何 append log.md
10. 如何执行 lint/health-check

**不把领域专业知识放进 KNOWLEDGE.md。它是治理规则，不是业务知识。**

## 7. Wiki Page Convention

轻量 Markdown + YAML frontmatter。

```markdown
---
title: 京东商智推广规则
type: platform_rule
domain: ecommerce
sources: [raw/platform/jd-商智-推广规则.pdf]
created_at: 2026-08-13
updated_at: 2026-08-13
tags: [jd, promotion, rule]
---

# 京东商智推广规则

## 核心规则
（自然语言 Markdown，LLM 可读）

## 交叉引用
- 相关：[[双11-大促案例]]

## 未决矛盾
- 规则 A 与规则 B 冲突，见 [[冲突记录]]
```

**不建大 schema。正文是自然语言 Markdown，供 LLM 消费。**

候选 metadata：title / type / domain / sources / created_at / updated_at / tags。

## 8. Ingest / Query / Lint Workflow

### Ingest（raw source → wiki updates）

```
Runtime 读取 raw/ 中新源材料
  → 判断是新建页面还是更新已有页面
  → 提取/总结/交叉引用/标注矛盾
  → 写 wiki/ 页面（含 source 引用）
  → 更新 index.md
  → append log.md
```

### Query（index → relevant wiki pages → answer）

```
Runtime 读 index.md 定位相关页面
  → 读 wiki/ 页面
  → 基于已有 Wiki 回答（不重新从 raw 推导）
```

### Lint（发现矛盾/陈旧/孤儿/缺交叉引用/知识缺口）

```
检查 wiki/ 一致性
  → contradictions（两源冲突未标注）
  → stale pages（source 已更新但 wiki 未更新）
  → orphan pages（无 index 引用）
  → missing cross-references
  → knowledge gaps
```

**暂无自动化引擎需求。操作可由 Runtime（LLM）执行。**

---

## 9. Provenance Rules

1. Wiki 页面必须保留对 raw source 的引用
2. **不把 Runtime 综合结果等同于 verified World Fact**（world/ 有 evidence/assertion 语义，knowledge/wiki/ 是"人类提供的知识"，不是"已验证事实"）
3. **两源冲突时保留 disagreement，不静默消解**

---

## 10. Minimal JD-domain Validation

只用几个样本知识项验证机制：

- 一个 platform/reference 文档（如京东商智推广规则）
- 一个 marketing/campaign 案例（如双11大促）
- 可选一个 organization/SOP 文档（如客服 SOP）

**不全量导入整个 JD corpus。目标是验证机制，不是建综合知识库。**

## 12. Success Criteria

1. Raw source 在 ingest 后保持不变
2. Runtime 能读一个 raw source 并创建/更新 Wiki Markdown
3. 新 source 能更新已有 Wiki 页面，而非总是新建
4. Wiki 页面保留 source provenance
5. index.md 被更新，能引导 Runtime 导航
6. log.md 记录 ingest/query/lint 操作
7. 冲突来源能共存，矛盾被显式表示
8. Blank Hermes session 能通过现有 Fabric Agent Workspace 发现并使用 Wiki 知识
9. Hermes 生成的 Memory/Skill 留在 Hermes Profile，不进 knowledge/wiki
10. 不引入 RAG/vector/search 子系统
