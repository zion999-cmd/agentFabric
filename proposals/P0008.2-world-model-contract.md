## 2. Contract (shared/schemas/world-model.ts)

### World Object（6 types）

```
system / surface / feature / metric / dimension / constraint
```

- `id` + `type` + `name` + `attributes`（intrinsic，非关系非值）
- 无 value（实时值属于 Observation）
- 无 relationship（关系是 Assertion）

### World Assertion（graph edge）

```
subjectId → predicate → objectRef
  + epistemicStatus（suspected/observed/verified）
  + temporalStatus（active/superseded/retired）
  + evidenceRefs[]
  + discoveredAt / source
```

Predicate: has_surface / has_metric / exposes_metric / supports_dimension / observable_by / accessible_via / has_constraint / belongs_to

### Capability Binding

```
worldObjectId → capabilityId（引用 CapabilityRegistry）
  + relationship（observable_by / exportable_by / comparable_by）
  + epistemicStatus
```

## 3. Review Concerns — Resolved

### ① Epistemic lifecycle ≠ Temporal lifecycle ✅ RESOLVED

两个正交生命周期，已在 schema 分离：

| 生命周期 | 状态 | 方向 | 含义 |
|---------|------|------|------|
| Epistemic（confidence） | suspected → observed → verified | 单调 | "我有多确定" |
| Temporal（world validity） | active → superseded / retired | 随世界变化 | "这还成立吗" |

示例（京东改版场景）：
```
Surface A → exposes → Metric X   [epistemic: verified]
                                       ↓ world changes
Surface A → exposes → Metric X   [temporal: superseded, supersededBy: new-assertion]
                                       epistemic 仍 = verified（当时确实验证过）
```

`supersedeAssertion()` 帮助函数：标记旧断言 superseded + 指向新断言，**不降级 epistemic**。

`isActiveKnowledge()` 区分：`temporalStatus === 'active' && isLearnableKnowledge()`——superseded 的 verified 断言不会被当作当前知识返回。

### ② evidenceRefs 是 reference interface，不是完整 provenance ✅ HONEST

Schema 已明确标注（P0008.1 Gap Map §6 known gap）：

> evidenceRefs 是 REFERENCE 接口。现有 Evidence contract（evidence/types.ts）为业务数据 acquisition 设计（shop_id/summary/trend），NOT World Discovery evidence（screenshot/DOM/network/documentation）。World Evidence semantics 未实现。

Contract 支持 provenance reference，但**不声称 provenance infrastructure 完整**。这是 P0008.3+ 的缺口。

### ③ CapabilityBinding 有明确 binding semantics ✅ RESOLVED

`bindingType` → `relationship`，enum 扩展为：

```
observable_by     — 该 World Object 可被此 Capability 观察（JD fixture 验证）
exportable_by     — 可被导出（CSV，reserved）
comparable_by     — 可被对比（跨平台，reserved）
```

不是两个 ID 的 bare association——`relationship` 表达"为什么绑定"。当前只有 `observable_by` 被 JD fixture 验证，其余 reserved。
