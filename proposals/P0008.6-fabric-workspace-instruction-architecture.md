# P0008.6 — Fabric Workspace Instruction & Exposure Architecture

**Date**: 2026-08-14 (revised after Architecture Review)
**Depends on**: P0008.2 (World Model Contract), P0008.3 (Agent Workspace & Runtime Integration), P0008.4 (Shared Knowledge Layer), P0008.5 (Bootstrap E2E)
**Supporting audits**: `audits/p0008.6-claudian-instruction-architecture.md`, `audits/p0008-operational-capability-exposure.md`
**Type**: Architecture Proposal — implementation follows this revision

---

## 1. Objective

让 **Situation Chat → Hermes Session → Fabric Workspace** 成为 P0008 的 canonical Runtime Path，并让一个正式启动的 Blank Runtime（无 JD Soul/Skill/Memory、无测试专用 prompt）能够发现和使用 Fabric 已经拥有/验证的：

- System Context（`systems/`）
- Shared Knowledge（`knowledge/`）
- Capabilities（`capabilities/`）
- Context Instructions / Navigation（`AGENTS.md` + 各 scope `INDEX.md`）

本 Proposal 的**核心是本阶段的 root `AGENTS.md`**——它必须让 Blank Runtime 具备 Orientation / Context Model / READ-side Routing / Epistemic Semantics / Ownership Boundary。

---

## 2. Problem（从两个 Audit 提炼，review 修正后）

1. **两条断开的生产 Runtime 路径**：P0008.3 session 路径与 Phase 3 legacy 路径没有桥接。CapabilityRegistry(11) 只在 legacy 路径可见，session runtime 只见 1 条 binding。

2. **Topology 未锁定**：`world/` vs `systems/`、`capability/` vs `capabilities/` 同时存在于代码与实验；`contracts/WORLD_MODEL.md` 是 dangling reference。

3. **World/System 消费失败**：P0008.5 已知 0/3。根因是 `systems/` 只有 WRITE-side 指令（构建）、无 READ-side 指令（消费）——缺 Routing + Epistemic Semantics + Navigation 指针。

4. **持久化被破坏**：`writeProjection` 每次启动 `rmSync(workspace)`，Agent 编译进 `knowledge/` 的内容重启即丢。

> Review 修正：**删除 procedures/ 层**。System Construction / Knowledge Ingestion 是 P0008.5 的 architecture evidence，不在本阶段新建 Procedure taxonomy 或 runtime asset。Fabric 最终提供 Learning Context，成长属于 Hermes——不讨论/管理 Hermes Skill。

## 3. Canonical Runtime Path

```
Situation Chat (Workspace UI)
        ↓ POST /api/situation/:id/chat
Situation Chat Bridge (platform/server/routes/situation-chat.ts)
        ↓ session.create(cwd = canonical workspace, profile = …)
Hermes Session (cwd → filesystem-native discovery)
        ↓ read AGENTS.md → route → INDEX → content/capability
Fabric Workspace
```

Legacy `/api/chat → Hermes oneShot → CapabilityBridge` 状态：

- **保留但冻结**：不再承载新的 P0008 runtime capability。
- CapabilityBridge 在 P0008 语境下重新定位为 **CapabilityProjector 的 authoritative reader**，不再是 runtime 直接调用的 path。

## 4. Canonical Workspace Topology

锁定为：

```
workspace/
├── AGENTS.md                    # root instruction（Hermes 原生加载）
├── README.md                    # human-facing orientation（最小）
├── systems/                     # System Context（Fabric 生成，READ-ONLY）
│   ├── INDEX.md                 # Navigation Map（系统列表 + 哪个 primitive 回答什么）
│   └── jd_shangzhi/             # systemId（P0008.2 内部术语不变）
│       ├── system.md            # System identity（店铺/星级/导航模块数…）
│       ├── surfaces.md
│       ├── features.md
│       ├── metrics.md
│       ├── dimensions.md
│       ├── constraints.md
│       └── assertions.md        # 含 epistemic + temporal status
├── knowledge/                   # Shared Knowledge（Agent-maintained，PERSISTENT）
│   ├── KNOWLEDGE.md             # governance（非业务知识）
│   ├── INDEX.md                 # Navigation Map
│   ├── log.md
│   └── <topic>/…                # compiled pages
├── knowledge-sources/           # immutable provenance（PERSISTENT）
│   └── raw/                     # 人类/外部源材料（只读）
└── capabilities/                # Runtime-facing Capability projection（生成，READ-ONLY）
    ├── INDEX.md                 # Navigation Map（11 capabilities + domain 分组）
    ├── bindings.md              # P0008.2 CapabilityBinding（relationship 语义）
    └── <capability-id>.md       # per-capability card（来自 CapabilityRegistry）
```

**解决的 drift**：

| 现状 | 锁定后 |
|------|--------|
| `world/` vs `systems/` | **`systems/`**（正式替代 Runtime-facing `world/`） |
| `capability/` vs `capabilities/` | **`capabilities/`** |
| `contracts/WORLD_MODEL.md` dangling | **删除该引用**。World Model 结构在 P0008.2 契约（`shared/schemas/world-model.ts`），消费侧只需 Navigation，无需 construction 指令 |

**关键原则**：

- `systems/`、`capabilities/`、`AGENTS.md`、`README.md` = **projection**（从 authoritative state 生成，可重建）。
- `knowledge/`、`knowledge-sources/raw/` = **persistent**（自己就是 source of truth，不可重建）。见 §8。
- `systems/INDEX.md`、`capabilities/INDEX.md` = **Navigation Map**，不承担 instruction。

## 5. Instruction Architecture（root AGENTS.md —— 本阶段核心）

Root `AGENTS.md` 是 Hermes 唯一原生从 cwd 加载的 instruction。借鉴 Claudian 的 orientation 思路（system prompt 教"我在哪/内容模型/怎么导航"），但**不复制 Claudian runtime**——agentFabric 无 runtime，orientation 必须落在这个文件里。

### 5.1 Orientation（我在哪）

- 我进入了一个 Fabric Agent Workspace。
- 这个 workspace 的 subject 是 **京东商智 + 具体店铺**（subject anchoring——P0008.5 失败第一环）。
- 我的 cwd 就是这个 workspace。

### 5.2 Context Model（有哪些 context source，各自语义）

| Source | 语义 | 谁写 |
|--------|------|------|
| `systems/` | 外部系统是什么（structured, verified World Model） | Fabric 生成 |
| `knowledge/` | 共享的组织/领域知识（compiled Read Model） | Agent 维护 |
| `knowledge-sources/raw/` | 源材料（immutable provenance） | 人类提交 |
| `capabilities/` | Fabric/connected system 可观察/可做什么 | Fabric 生成 |

### 5.3 Routing（READ-side，按 Context source semantics，**不是 filesystem-first**）

```
问题类型                                → 路由
外部系统的事实（是谁/指标/维度/导航/约束）  → systems/INDEX.md → primitive
共享组织/领域知识（方法/规则/案例/SOP）    → knowledge/INDEX.md → pages
可用观察/动作（"Fabric 能观察/做什么"）    → capabilities/INDEX.md

只有满足以下之一时，才用 Runtime native external tools（web_search 等）：
  (a) local Context 不足以回答
  (b) 明确需要 freshness / current / real-time 数据
  (c) 需要继续探索外部世界
```

**关键**：Routing 表达的是"**问题语义 → 对应 context source**"，不是"一律先读本地文件"。避免了 P0008.4 acceptance 暴露的"filesystem-first 被 research 默认行为覆盖"问题。

### 5.4 Epistemic Semantics（**不得与 freshness 混淆**）

- `systems/` 的 assertion 携带 **epistemic status**（`verified` / `observed` / `suspected`）= 该断言在**发现时**被确认的置信程度。
- **temporal status**（`active` / `superseded` / `retired`）= 该断言当前是否仍成立（P0008.2，正交于 epistemic）。
- **`verified` 不表示"比实时外部来源更新"**。它只表示"在发现时被确证"。
- 当任务需要 freshness / current / real-time 数据时，按 Routing 走 external tools——不要假设 `systems/` 是最新鲜的。

### 5.5 Ownership / Boundaries

- `systems/`、`capabilities/`、`knowledge-sources/raw/` **READ-ONLY**。
- `knowledge/` 是唯一可写区（按 `knowledge/KNOWLEDGE.md` 维护）。
- Memory / Skill / Soul / Session 属于 Runtime Profile，**不进 workspace**。

### 5.6 约束

- **INDEX 只做 Navigation**，不含 instruction、不含答案。
- **不新增 scoped AGENTS.md**。唯一 instruction 是 root `AGENTS.md`；`knowledge/KNOWLEDGE.md` 是既有 governance（描述性命名，保留）。

## 6. Capability Exposure

**CapabilityRegistry 仍是 authoritative capability source**（`generated/capability-contract.json`，11 capabilities）。

新增 **CapabilityProjector**：读 CapabilityRegistry → 投影 `capabilities/`：

- `capabilities/INDEX.md`：Navigation Map（列出全部 11 capabilities，按 domain 分组）。
- `capabilities/<capability-id>.md`：per-capability card（name / id / domain / 观察什么指标 / acquisition / outputs）。
- `capabilities/bindings.md`：**P0008.2 CapabilityBinding 的忠实投影**（worldObjectId ↔ capabilityId 的 relationship 语义）。

**关键约束**：

1. **投影，不复制、不重新定义**。card 内容来自 CapabilityRegistry contract 字段，只做 JSON → Markdown 格式转换。
2. **P0008.2 CapabilityBinding contract 不得被 Markdown presentation 替代或删除**。binding 是独立契约（`shared/schemas/world-model.ts`），projector 忠实渲染为 `capabilities/bindings.md`，不折叠进 assertion 或 card。
3. Registry 与 workspace **同源**：每次启动从 authoritative registry 重建 `capabilities/`，drift 不可能发生。

## 7. Persistent Knowledge Ownership

**问题**：`writeProjection` 的 `rmSync(workspace, recursive)` 把 `knowledge/` + `knowledge-sources/raw/` 一并清空。

**修复（最小，不扩大范围）**：把 workspace 目录按性质分两类：

| 目录 | 策略 | 重启后 |
|------|------|--------|
| `AGENTS.md` / `README.md` / `systems/` / `capabilities/` | **project / regenerate**（清空重建） | 重建，不丢 |
| `knowledge/` / `knowledge-sources/raw/` | **ensure / seed-if-absent**（幂等，不覆盖） | 保留 |

**实现约束**：

- `writeProjection` **绝不 `rmSync(workspace 根)`**，只清空它 owned 的 regenerable 子目录（`systems/`、`capabilities/`）+ 覆盖 `README.md` / `AGENTS.md`。
- `initSharedKnowledgeLayer` 对 `knowledge/` **只 seed 结构 + 首次 seed 页面**，对 Agent 已生成的页面**永不覆盖、永不删除**。
- **不引入**新的 storage / database / sync / git-versioning architecture。

**source of truth / write-back**：Agent 写 `knowledge/` 就是写 source of truth（knowledge 自己就是 authoritative Read Model）；`systems/`、`capabilities/` 是 projection，Agent 的写**永不**反向写回 authoritative state（投影单向）。

---

## 8. Ownership Boundaries（Fabric vs Runtime）

| 类别 | Fabric-owned | Runtime-owned |
|------|--------------|---------------|
| Workspace topology / instructions / governance / INDEX | ✅ | — |
| `systems/`（生成 + 内容） | ✅ | — |
| `knowledge/`（治理 + 持久） | ✅ | — |
| `capabilities/`（投影） | ✅ | — |
| SOUL / Memory / Skills / 成长 | — | ✅（Hermes） |
| Sessions / Plans | — | ✅ |
| file tools / approval | — | ✅ |
| instruction loading | 提供文件 | ✅ 原生从 cwd 加载 |

三条铁律：

1. Fabric **绝不**创建/注入/改写 Runtime 的 SOUL / Memory / Skill / Session；**不管理 Hermes 成长**。
2. Fabric 的"只读"是 **Instruction Policy**，不是安全机制；enforcement 是 Runtime 的 approval/permission。
3. Capability 是 Fabric 的投影，不是 Runtime 的 skill。

## 11. Implementation Breakdown（高层）

1. **Instruction**（`shared-knowledge/contract.ts`）：重写 `AGENTS_CONTRACT`——Orientation / Context Model / Routing / Epistemic Semantics / Ownership；`world/`→`systems/`、`capabilities/`→`capabilities/`；删除 `contracts/WORLD_MODEL.md` dangling 引用。

2. **Projector**（`fabric-workspace/projector.ts`）：`world/`→`systems/`，新增 `systems/INDEX.md`（navigation），`capability/`→`capabilities/`（保留 bindings.md）。

3. **CapabilityProjector**（新）：读 CapabilityRegistry → `capabilities/INDEX.md` + per-capability cards。

4. **Persistence 修复**（`situation-chat.ts` / `fabric-workspace/index.ts`）：`writeProjection` 不再 `rmSync(workspace 根)`，只清空 regenerable 子目录；`initSharedKnowledgeLayer` 幂等 seed。

5. **fixture enrichment**（`jd-fixture.ts`）：补 P0008.5 已提取的三个 known-fact。

6. **Acceptance**：复用 P0008.5 的 Blank Hermes 探针方法，跑 A1–A4。
