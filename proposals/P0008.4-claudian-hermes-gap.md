## 1. 关键发现：Claudian 和 Hermes 遵循同一个 Delegation Pattern

Claudian 不是自含 LLM runtime——它是 Obsidian 插件，把 Claude Code/Codex 等 provider CLI 当 subprocess 启动。

**Claudian 自己不解析 AGENTS.md/CLAUDE.md**，而是把 cwd 设为 vault root，让 provider CLI 原生去读。

```python
# Hermes prompt_builder.py 同样原生读 context files（我直接验证）
build_context_files_prompt():
  1. .hermes.md / HERMES.md  (walk to git root)
  2. AGENTS.md / agents.md   (cwd only)
  3. CLAUDE.md / claude.md   (cwd only)
  4. .cursorrules            (cwd only)
  SOUL.md                    (HERMES_HOME, independent identity)
```

**Claudian 的完整 chain**（从源码追踪）：

```
AGENTS.md/CLAUDE.md → provider CLI 从 cwd 原生加载（Claudian 委托，无自有 parser）
prompt/bootstrap → buildSystemPrompt() → Options.systemPrompt
cwd/vault → Options.cwd = vault root
file tools → provider CLI 原生（Read/Write/Edit/Glob/Grep/LS/Bash），Claudian 不重实现
write approval → 4 层：permission mode(yolo/plan/safeMode) → tool policy → canUseTool → rule persistence
session → provider 原生 JSONL transcripts + Claudian 自己的 .claudian/sessions 元数据
```

**Claudian 的 Instruction/Knowledge/Memory 三层**：
- Instructions = system prompt + custom instructions + 原生 AGENTS.md/CLAUDE.md
- Knowledge = vault 的 Markdown notes（"second brain"）
- Memory = 无独立模块——provider 原生 CLAUDE.md/AGENTS.md + session transcripts

## 2. Hermes 原生能力（绝不能复制）

| 机制 | Hermes 位置 | 说明 |
|------|-----------|------|
| AGENTS.md/CLAUDE.md/HERMES.md/SOUL.md 加载 | `prompt_builder.py:build_context_files_prompt` | 从 cwd 原生加载，优先级 HERMES.md → AGENTS.md → CLAUDE.md → .cursorrules |
| 文件工具 | `tools/file_tools.py` 等 | Read/Write/Edit/List/Search 原生 |
| 危险命令审批 | `tools/approval.py` | pattern 检测 + per-session 状态 + hardline 永不绕过 |

| Session 持久化 | `state.db` + `sessions/` | create/resume/compression |

**核心结论**：指令加载、文件工具、审批门、session、memory/skill 全部是 Runtime（Hermes/Claude Code）原生能力。agentFabric 复制任何一个都是架构错误。

## 4. Gap（回答三个问题）

### Q1: KNOWLEDGE.md 是否足够？

**不够。**

KNOWLEDGE.md 是 **knowledge 层的治理规则**（如何维护 Shared Knowledge），不是 **Workspace-level Agent Instruction**（如何在这个 workspace 工作）。

且 KNOWLEDGE.md 在 `knowledge/` 子目录——Hermes 原生只加载 cwd root 的 AGENTS.md/CLAUDE.md，不会自动加载 `knowledge/KNOWLEDGE.md`。

### Q2: 是否需要 Workspace-level Agent Instruction？

**需要。** 这是一个真实缺口。

当前 Fabric Workspace 只有 `README.md`（3 行 orientation），而 **Hermes 不加载 README.md**。所以 Blank Hermes 进入 workspace 时：

- 没有任何 instruction 告诉它：workspace 结构（world/ + knowledge/）、它的角色、该读什么、怎么工作
- 它看到文件但不知道 "world/ 是只读的 World Model，knowledge/ 是我要维护的 Shared Knowledge，维护规则在 KNOWLEDGE.md"

**缺失的是 workspace root 的一个 `AGENTS.md`（或 `CLAUDE.md`）**，Hermes 会原生加载，内容类似：

```
# Fabric Agent Workspace — Agent Instruction

你是进入 Fabric Agent Workspace 的业务 Agent。

## Workspace 结构
- world/           — 外部世界的 World Model（只读，Fabric 生成）
- knowledge/       — Shared Knowledge（你按 KNOWLEDGE.md 维护）
- knowledge-sources/raw/ — 不可变原始来源（只读）

## 你的角色
- 读取 world/ 理解外部世界结构
- 读取 knowledge/ 获取人类共享知识
- 按 knowledge/KNOWLEDGE.md 治理规则维护 Shared Knowledge

## 边界
- world/ 只读，绝不修改
- 你的 Memory/Skill 属于你自己（HERMES_HOME），不进这里
```

### Q3: 哪些机制属于 Hermes 原生，绝不能复制？

| 机制 | 归属 | agentFabric 动作 |
|------|------|----------------|
| AGENTS.md/CLAUDE.md/SOUL.md 加载 | Hermes 原生 | ✅ 只需在 workspace root 放一个 AGENTS.md，Hermes 自动加载 |
| 文件工具（read/write/edit） | Hermes 原生 | ✅ 不重实现 |
| 审批门（dangerous command + write_approval） | Hermes 原生 | ✅ 不绕过，不重实现 |
| Session 持久化 | Hermes 原生 | ✅ 不重实现 |
| Memory/Skill/SOUL | Hermes 原生 | ✅ 不接管 |

## 5. 最终结论

**Claudian 的启示不是"做什么"，而是"不做什么"**：

Claudian 把指令加载、文件工具、审批门、session 全部委托给 provider CLI，自己只做：设置 cwd、注入 system prompt、路由审批、session bookkeeping。

agentFabric 应该遵循同样的 Delegation Pattern：

```
agentFabric 提供：
  - cwd（Fabric Workspace）
  - 结构（world/ + knowledge/ + knowledge-sources/raw/）
  - governance（KNOWLEDGE.md）
  - ← 缺失：workspace root 的 AGENTS.md（Agent Instruction）

Hermes 原生提供（不复制）：
  - AGENTS.md/CLAUDE.md 加载（从 cwd）
  - 文件工具 + 审批门
  - session + memory/skill/soul
```

**唯一需要补的 agentFabric 资产**：workspace root 的一个 `AGENTS.md`，把"结构 + 角色 + 边界"告诉 Hermes，让 Hermes 原生加载后知道如何在这个 workspace 工作、如何维护 knowledge/、如何按 KNOWLEDGE.md 治理。

这是 P0008.4 真正缺的最后一公里，不是 Wiki Engine / RAG / 审批系统。
