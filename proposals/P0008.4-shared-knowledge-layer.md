# P0008.4 — Agent Shared Knowledge Layer

**Date**: 2026-08-13
**Depends on**: P0008.1 / P0008.2 / P0008.3
**Type**: Design Proposal — no implementation

---

## 1. Objective

agentFabric 给 Runtime 的知识不能只有 World Knowledge。业务 Agent 还需要读取：平台规则、新推广方式、营销案例、行业资料、企业 SOP、品牌规范、组织知识、外部研究资料。

这些属于 **Shared Knowledge**，不属于 World Model / Learning Context / Hermes Memory-Skill-Soul。

P0008.4 定义一种机制：把 Human / External Raw Knowledge 持续编译成 Agent 容易消费的 Shared Knowledge，并通过 P0008.3 Agent Workspace 提供给 Runtime。

**核心对象是 Shared Knowledge，不是 "Wiki"。**

参考 Andrej Karpathy 的 LLM Wiki **知识维护 Pattern**（不是其产品边界）：

```
Raw Sources → LLM-maintained persistent knowledge → Governance/Rules
```

---

## 2. Architecture Intent

P0008.4 要表达的不是：

> "agentFabric 提供一个 LLM Wiki。"

而是：

> "agentFabric 提供一种机制，把 Human / External Raw Knowledge 持续编译成 Agent 容易消费的 Shared Knowledge，并通过 P0008.3 Agent Workspace 提供给 Runtime。"

```
Human / External Knowledge
          ↓
   Immutable Sources
          ↓
 Agent Compilation
          ↓
  Shared Knowledge
          ↓
  Agent Workspace
          ↓
     Any Runtime
```

Karpathy LLM Wiki 是这一机制的重要设计参考，不是 agentFabric 的产品边界。

---

## 3. Core Principles（从 Karpathy 借鉴的机制）

1. **Raw source immutable** — 原始来源只读，永不改写
2. **Persistent knowledge** — 知识持久化，不重建
3. **Compounding maintenance** — 知识持续积累，新资料更新已有知识
4. **One source may update multiple knowledge pages**
5. **Cross-reference** — 维护交叉引用
6. **Contradiction preservation** — 两源冲突保留 disagreement，不静默消解
7. **Provenance** — 知识页面保留对 raw source 的引用
8. **INDEX** — 导航入口
9. **Maintenance log** — 记录维护历史
10. **Governance rules** — 规定维护流程
11. **Ingest / Query / Lint** — 概念性操作

**核心区别（vs RAG）**：persistent knowledge 会随资料增加持续变丰富；RAG 每次 Query 临时拼装 chunks。

**Raw → Knowledge 不是文件格式转换**（PDF→Markdown→完成 是错的）。一个 Raw Source 可能：阅读 → 分类 → 创建页面 → 更新已有页面 → 加交叉引用 → 更新 INDEX → 标记矛盾 → 记录 log。

## 4. Four-Layer Agent Context Environment

```
Agent Context Environment
├── world/                          "外部世界是什么"         Fabric / P0008.2
├── knowledge/                      "人类提供了哪些共享知识"  Fabric / P0008.4
├── Situation + Learning Context    "现在/协作中发生了什么"   Fabric / P0007
└── Hermes Profile                  "Runtime 自己记住了什么"  Hermes-owned
                                     Memory / Skill / Soul
```

前三层是 Fabric 向 Runtime 提供的 Context。第四层属于 Runtime Self。

**绝不合并这四层。**

---

## 5. Ownership

```
Fabric-owned source storage
├── knowledge-sources/
│   └── raw/           — 人类/外部提供的源材料（immutable，provenance source）

Fabric Agent Workspace
├── world/             — P0008.2 World Model projection
└── knowledge/         — Agent-consumable Shared Knowledge Read Model
    ├── KNOWLEDGE.md   — Agent Shared Knowledge Governance Contract
    ├── INDEX.md       — Agent Knowledge Map / Navigation Entry
    ├── log.md         — maintenance log（append-only）
    ├── platform/
    ├── cases/
    ├── operations/
    └── organization/

Hermes Profile（agentFabric 之外）
├── SOUL / Memory / Skills / Sessions / Plans
```

**关键 ownership 定义**：

- `knowledge-sources/raw/` = **provenance source**（immutable，Agent 只读）
- `knowledge/` = **Agent-consumable Shared Knowledge Read Model**（Agent 维护）
- `knowledge/*.md` **不是 canonical truth**——它是 Agent 对 source material 的整理、综合和结构化表达，可能包含 inference、uncertainty 和 disagreement

**Hermes Profile 保持在 agentFabric Shared Knowledge ownership 之外。**

## 5.1 AGENTS.md — Fabric Agent Workspace Contract

workspace root 新增 `AGENTS.md`，作为 **Fabric Agent Workspace Contract**。

它是 Hermes（或任何支持 AGENTS.md/CLAUDE.md convention 的 Runtime）**原生从 cwd 加载**的顶层指令。

它只描述：

- **Workspace topology**：world/ + knowledge/ + knowledge-sources/raw/
- **Context semantics**：每层含义（world = 世界是什么；knowledge = 人类共享了什么；raw = 原始来源）
- **Ownership & boundaries**：world/ 只读、raw/ 只读、knowledge/ 可写；Memory/Skill/Soul 属 Runtime 自己
- **指引**：维护 Shared Knowledge 时读 knowledge/KNOWLEDGE.md

**关键约束**：

- **不复制 KNOWLEDGE.md 内容进 AGENTS.md**——AGENTS.md 只指向 KNOWLEDGE.md
- **不实现 instruction loader**——Hermes 原生加载 AGENTS.md
- **不实现 file/write/approval/session**——全部委托 Hermes

```
AGENTS.md（workspace root）       ← Hermes 原生加载
  ↓ 指向
knowledge/KNOWLEDGE.md           ← 治理规则（Agent 主动读）
```

## 5.2 Markdown 定位

## 6. Markdown 定位

Markdown 不是因为"我们要做 Wiki"。而是因为：

> Markdown 是当前 Runtime filesystem-native、LLM-friendly、human-inspectable 的最低复杂度知识表示。

- **Primary consumer**：Agent Runtime
- **Secondary consumer**：Human inspection / correction

Human-readable 是优势，但不是 P0008.4 的首要消费者设计目标。

---

## 7. KNOWLEDGE.md — Agent Shared Knowledge Governance Contract

KNOWLEDGE.md 告诉任何进入 Workspace 的 Runtime 如何维护 shared knowledge：

1. 如何读取 source
2. 如何维护 shared knowledge
3. 如何判断 create vs update
4. 如何保留 provenance
5. 如何表达 uncertainty
6. 如何处理 disagreement
7. 如何建立 cross-reference
8. 如何维护 INDEX
9. 如何记录 maintenance log

**它不是**：Wiki configuration / Business Skill / Runtime Soul / Runtime Memory。

它是 governance，不是业务知识。

---

## 8. INDEX.md — Agent Knowledge Map / Navigation Entry

INDEX.md 不是 Wiki homepage，而是 **Agent Knowledge Map**。

典型 Runtime discovery：

```
KNOWLEDGE.md
      ↓
knowledge/INDEX.md
      ↓
relevant knowledge pages
      ↓
follow references
      ↓
source（only when necessary）
```

目的：让 Agent 优先消费已整理好的 Shared Knowledge，而不是每次任务重新阅读全部 Raw Sources。

## 9. Knowledge Page Convention

轻量 Markdown + YAML frontmatter。

```markdown
---
title: 京东商智推广规则
type: platform_rule
domain: ecommerce
sources: [knowledge-sources/raw/jd-promotion.pdf]
created_at: 2026-08-13
updated_at: 2026-08-13
tags: [jd, promotion, rule]
---

# 京东商智推广规则

## 核心规则
（自然语言 Markdown，LLM 可读）

## 交叉引用
- 相关：[[双11大促案例]]

## 未决矛盾
- 规则 A 与规则 B 冲突，见 [[冲突记录]]
```

**不建大 schema。正文是自然语言 Markdown，供 LLM 消费。**

## 10. Ingest / Query / Lint Operations

### Ingest（Raw source → Shared Knowledge updates）

```
Agent 读取 knowledge-sources/raw/ 新源材料
  → 判断 create vs update
  → 提取/总结/交叉引用/标注矛盾
  → 写 knowledge/ 页面（含 source 引用）
  → 更新 INDEX.md
  → append log.md
```

### Query（INDEX → relevant pages → answer）

```
Agent 读 INDEX.md 定位相关页面
  → 读 knowledge/ 页面
  → 基于已整理知识回答（必要时才回 raw）
```

### Lint（发现矛盾/陈旧/孤儿/缺交叉引用/知识缺口）

```
检查 knowledge/ 一致性
  → contradictions（两源冲突未标注）
  → stale pages
  → orphan pages
  → missing cross-references
  → knowledge gaps
```

**暂无自动化引擎。操作由 Agent（LLM）执行。**

---

## 11. Maintenance Log

log.md 记录：ingest / update / contradiction discovered / lint / source relationship changes。

**但不要演化成**：event sourcing / audit platform / version control system。Git/filesystem 已承担基础历史能力。第一阶段保持 append-only。

---

## 12. Provenance Rules

1. Knowledge 页面必须保留对 raw source 的引用
2. **不把 Agent 综合结果等同于 verified World Fact**（world/ 有 evidence/assertion 语义；knowledge/ 是"人类提供的知识"，可能含 inference/uncertainty）
3. **两源冲突保留 disagreement，不静默消解**

---

## 13. Minimal JD-domain Validation

用样本知识项验证完整 lifecycle：

- **Source A（platform reference）**：京东推广方式资料 → ingest → 创建 knowledge 页面
- **Source B（case）**：营销案例 → ingest → 创建/更新页面 + cross-links
- **Source C（organization）**：内部运营 SOP → ingest → 更新 INDEX
- **Source D（conflict）**：与已有知识冲突的资料 → 验证 Agent 是否保留两 source、标记 contradiction、不静默覆盖

**不全量导入 JD corpus。验证机制，不建综合知识库。**

## 15. Success Criteria

1. Raw source 在 ingest 后保持不变
2. Agent 能读一个 raw source 并创建/更新 knowledge Markdown
3. 新 source 能更新已有 knowledge 页面，而非总是新建
4. Knowledge 页面保留 source provenance
5. INDEX.md 被更新，能引导 Agent 导航
6. log.md 记录 ingest/query/lint 操作
7. 冲突来源能共存，矛盾被显式表示
8. Blank Hermes session 能通过 Fabric Agent Workspace 发现并使用 knowledge 知识
9. Hermes 生成的 Memory/Skill 留在 Hermes Profile，不进 knowledge/
10. 不引入 RAG/vector/search/Wiki Engine 子系统
