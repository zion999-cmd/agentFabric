P0005.4 — Capability Runtime Layer (Consumption Engine)

🧭 背景（为什么要做 P0005.4）

当前系统已经完成：

P0005.2 → Discovery Engine（70 APIs / 887 rules / 7 contexts）
P0005.3 → Capability Generator（blueprint / parser-plan / indicator.generated）

但存在一个明确断裂：

Discovery → Capability → ❌ Connector 未消费

🧠 P0005.4 的本质

不是：

❌ Runtime Execution Layer

也不是：

❌ Blueprint-driven system redesign

而是：

✅ Capability → Connector Binding Layer（能力接入层）

🎯 核心目标

把以下“静态生成物”：

generated/
  connector-blueprint.json
  parser-plan.json
  normalizer-plan.json
  indicator.generated.json
  manifest.generated.json

变成 Connector 的唯一事实来源（Single Source of Truth）

🧱 新架构定位
P0005.2 Discovery
        ↓
P0005.3 Capability Generator
        ↓
P0005.4 Connector Binding Layer   ←（本次）
        ↓
Connector Runtime (JD / Tmall / future platforms)
        ↓
Signals / Evidence / SQLite
📦 P0005.4 做什么（ONLY 3 THINGS）
1️⃣ Capability Artifact Loader

新增模块：

apps/ecommerce/connectors/binding/

负责：

读取 generated/*
校验 schema（Zod）
统一输出 runtime 可用结构
输入
generated/
  blueprint.json
  parser-plan.json
  normalizer-plan.json
  indicator.generated.json
  manifest.generated.json
输出
BoundCapabilityModel

包含：

api_routes
parser_rules
indicator_mapping
context_definitions
2️⃣ Connector Logic 替换（核心）
当前问题：

Connector 是：

hand-written API list (5 endpoints)
hand-written indicator-map (8 rules)
hand-written manifest (5 contexts)
P0005.4 目标：

Connector 改为：

❗ 不再定义能力，只执行能力

变化：
❌ BEFORE
cdp-client.ts
  → route("summary.ajax")
  → route("getProductList")
✅ AFTER
binding/connector-runtime.ts

for each api in blueprint.api_routes:
    execute(api)
3️⃣ Execution Contract 统一

新增标准执行协议：

CapabilityExecutionPlan

结构：

{
  platform: "jd",
  api_calls: [],
  parsing_rules: [],
  indicator_resolution: [],
  normalization_rules: []
}

Connector 只做：

plan → fetch → parse → normalize → emit evidence
🔥 关键设计原则（非常重要）
1. Capability is data, not code

能力不再写在：

manifest.ts
indicator-map.ts
cdp-client.ts

而是：

generated/*.json

2. Connector is pure executor

Connector 不再：

决定 API
决定指标
决定 context

只：

execute capability plan

3. Runtime is NOT involved

⚠️ 明确边界：

Runtime（Hermes）不理解 capability
Runtime 只消费 normalized signals
