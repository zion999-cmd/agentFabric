# P0007.1 Temporal Semantics Audit

**Scope**: Every production time source, every test time fixture.  
**Finding**: Zero hardcoded production times. One demo cosmetic. Test fixtures cleanly isolated.

---

## 1. Production Time Sources — All Real

| Module | Time Field | Source | Verdict |
|--------|-----------|--------|---------|
| Evidence Store | `acquired_at` | `new Date().toISOString()` | ✅ Real system time |
| Evidence Store | `processed_at` | Set by pipeline when processing | ✅ Real system time |
| Signal Pipeline | `observed_at` | `source.ingested_at` (pipeline run time) | ✅ Derived from real time |
| Signal Normalizer | `observed_at` | `input.timestamp` (collector input) | ✅ From collector event |
| Signal Normalizer | `expires_at` | `Date.now() + 24h` | ✅ Real system time |
| Runtime Kernel | `executionDate` | `date ?? new Date().toISOString()` | ✅ Real system time fallback |
| CDP Client | date list | `new Date(fromDate)` → date iteration | ✅ Real dates from CLI input |
| Chat Route | `ctx.date` | `context.date ?? new Date()` | ✅ Real system time fallback |
| SSE Demo | event timestamps | `new Date().toISOString()` | ✅ Real system time |
| Learning Context | all time fields | `IsoDateString` — no default | ✅ No default — caller must provide |
| CapabilityBridge | N/A | No time handling | ✅ Stateless |

**Zero hardcoded date strings in production code.** Every timestamp comes from `new Date()` (system clock), from external input (CLI flag, API request), or from evidence metadata (real acquisition time).

## 4. Time Semantics — No Ambiguity

Every time field has a distinct, documented meaning:

```
Evidence acquired_at:     "when Chrome CDP intercepted the API response"
Signal observed_at:       "business observation time from collector input"
Execution event timestamp: "when the Kernel emitted this event"
Situation observedAt:    "when the business situation was first detected"
ObservationRef.observedAt: "when the data was observed/captured"
AgentActivityRef.timestamp: "when the agent performed this activity"
HumanIntervention.timestamp: "when the human intervened"
ActionRef.timestamp:     "when the action was taken"
OutcomeRef.observedAt:   "when the outcome was re-observed"
LearningContext.createdAt: "when this context document was first assembled"
LearningContext.updatedAt: "when this context was last enriched"
```

No two fields share the same semantic. No field defaults to another field's value.

---

## 5. Conclusion

**No production time bugs.** The JD test conflation found earlier (`f5f3bb1`) was a test-only semantic note, not a production issue. Test fixtures use deterministic constants; production uses `new Date()` or external time sources.

The chain is clean:

```
JD API response time (from CDP)
  ≠ Evidence acquired_at (from system clock at capture)
    ≠ Signal observed_at (from pipeline run)
      ≠ Context createdAt (from context assembly)
```

None of these are conflated in production code.
